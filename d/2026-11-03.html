    Introducing the Grid Protectors Program

    OpenAI’s Grid Protectors Program will work with utilities to help future compute campuses support grid reliability and protect consumer electricity costs.

    • OpenAI 啟動 Grid Protectors Program，與電力公司、監管機關與政策制定者合作，設計未來算力園區在電網吃緊時可降載的安排，把園區的用電彈性變成電網可調度的資源。
    • 首個試點是喬治亞州 Effingham County 園區：全額支付供電所需的基礎設施與服務成本，並與 Georgia Power 協議最高 1,000 MW 的需求反應彈性，約等於 70 萬戶平均用電，比華府與波士頓的家庭數加起來還多。
    • 成本邏輯是電網固定成本不分尖離峰：園區全年穩定用電可分攤線路與變電成本，尖峰時降載則可少蓋為滿足尖峰而生的新機組，Georgia Power 估算其大負載合約組合可讓 2029 年起每年為用戶省約 9.5 億美元、典型住宅每月至少 15 美元。
    • 除降載外也會視當地需求用現地發電或儲能、以電池與電力控制平滑負載變化，並以長約與財務保證在其他客戶面臨專案延宕、縮減或取消時提供保護。
    • 明確立場：家庭與小企業不該補貼算力園區的用電，大型設施要自己付成本並協助電力公司管理系統；同時承認彈性不能取代新增發電與輸配電投資——美國資料中心容量預計 2030 年超過 100 GW。

    LifeVal 導讀

    Introducing LifeVal, a benchmark measuring how well AI helps people complete everyday tasks, from finding childcare to managing finances and government paperwork.

    • LifeVal 是 OpenAI 新公布的評測，衡量模型能不能真的「把事情辦完」，而不只是給建議；題目涵蓋托育、醫療、教育、家務行政、個人理財、購物、政府服務申請。
    • 題目來源不是憑空設計：先從美國時間使用調查（ATUS）與跨國時間使用研究（MTUS）整理日常任務清單，再對 3,995 位具人口代表性的受訪者調查，找出人們最想請助理代勞的事。
    • 範例與目前分數：搬家後挑幼兒園 93.1%、洪災前組織社區志工 98.0%、在 Luzerne County 找到符合預算＋獨立居住單元＋通勤條件的房子並把產權文件放進購物車 100%、遠端陪奶奶看球賽 96.3%、為剛確診糖尿病的長輩準備第一週照護與菜單 90.4%。
    • 過去一年分數提升的關鍵是把 browser use、computer use 與 connectors 任務上的能力與對齊度練上來，也讓 ChatGPT 從聊天工具走向「代理型個人助理」。
    • 方法論意義：以人真正在意的事取代純學術測驗來追蹤進展，並主張 AGI 是否造福所有人要用這種指標來驗證。

    Qodo builds context into AI code review with Codex 導讀

    Qodo brings company knowledge and coding standards into Codex, helping developers catch P0 issues across repositories before opening a pull request.

    • Qodo 在 Codex 市集推出外掛，把公司程式碼知識、組織規則與獨立審查（Qodo Agentic Toolbox）帶進 Codex 的開發工作階段，執行長 Itamar Friedman 稱 Qodo 是「寫程式代理最好的朋友」。
    • 要解的是跨儲存庫依賴：客戶環境可達 1 萬個以上 repo，本地看似正確的改動可能弄壞下游服務；補上脈絡後，Codex 能跨不同 Git 供應商、乃至透過 Kafka 串接的服務看整體，因此抓得到 P0 級 bug。
    • 工作流是：Codex 動手前先取回相關規則與 PR 歷史，改完後 Qodo 在同一 session 內把審查結果回給 Codex，開發者開 PR 之前就看到問題，形成「寫程式的代理」與「審查的代理」互相詰問的陰陽架構。
    • 產品觀：兩個角色各自需要獨立設定與脈絡（也可能各有多個代理），最終只把彼此沒有共識的爭點丟給人看，開發者從寫手變成規劃者與審查者，這是「軟體工廠」的基礎。
    • 下一步會用 OpenAI 新推出的 Decisions API 決定某階段該套用哪幾條規則（例如先從 200 條規則篩出真正該檢查的，再交給模型推理），比讓模型決定一切更快更便宜；內部也用 GPT-6 Astra 的 Extra High／Ultra 設定排程週報與檢視自己的程式變更。

    Make long-running agents faster with message threads 導讀

    New in the Messages API, send your conversation once, and the API receives only what’s new with every turn.

    • Anthropic 在 Messages API 推出 message threads（公開 beta）：代理不必每輪重送整段對話，只送新訊息加上前一個回應的 ID，直接攻擊 long-running session 的首字延遲。
    • 效果量測：Claude Code 多數使用者已預設開啟，500k 至 1M token 的請求首字延遲（TTFT）中位數下降約 35%；脈絡越多，省下的延遲越明顯。
    • 機制與限制：第一輪送完整對話並建立 thread，之後只送增量；thread 在各輪之間以加密形式留在記憶體、不寫入磁碟，最後一次請求後 5 分鐘過期，客戶端需重送完整對話開新 thread。
    • 關鍵取捨：請求變小但 Claude 每輪仍會讀完整對話，所以 token 用量不變——省的是延遲，不是成本。
    • 適用於延遲敏感的活躍 session（例如一次 session 內發出數百次請求的 coding agent）；原生 Claude Platform、AWS 上的 Claude Platform、Microsoft Foundry、Google Cloud 上的 Claude 模型皆可用，費率與速率限制照舊。

    New context engineering challenges in late 2026 導讀

    LangChain CEO Harrison Chase shares insights into the biggest harness engineering challenges with the emergence of proactive agents.

    • LangChain 執行長 Harrison Chase 指出，業界已收斂到「LLM 跑迴圈 + 呼叫工具 + 沙箱」的代理架構（Claude Code、Deep Agents 都是），因此有人認為難題已解；但轉向主動、常駐、目標導向的代理後，一整批新問題浮現。
    • 第一關是「主動而不擾民」：背景代理靠事件流或心跳喚醒，要能主動推訊息才有幫忙的感覺，推太多又會淹沒使用者，這個劑量拿捏仍是未解難題。
    • 記憶的難點不在資料結構（通常只是檔案或一段字串），而在決定「該記什麼」的智慧層——記得太多太細與完全不記一樣糟，而這層本身往往就是一個小代理。
    • 非同步與目標追蹤：長時間執行的工具與子代理變多，主代理要維持對使用者的即時回應，還要處理「工作完成時怎麼通知」、「主代理正在跑／已結束／等人核可」等狀態；代理從做完任務變成朝目標前進，得能拆目標、做實驗、取回饋並在長時程保持一致。
    • 對齊與瀏覽器：目標設計很難防代理作弊（經典例子「清掉所有 bug」→ 乾脆把程式碼刪光），harness 要讓代理專注目標又不至於過度優化；對通用代理而言瀏覽器正取代 bash 成為關鍵工具，而 DOM 與截圖都是巨大物件，脈絡管理比終端機難得多。
