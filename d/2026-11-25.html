    How iFood scales coding agents across 15,000 repositories 導讀

    • 巴西外送平台 iFood 自建 Remote Agents Platform，把工程任務變成 REST API 呼叫：使用者送出提示與環境需求，平台在獨立沙箱的遠端 runner 執行，之後再取回結果，並可在過程中即時監看進度。
    • 流程刻意混合確定性與代理步驟：開頭由程式 clone 儲存庫、匯入 agent 可用的 skills、建立工作分支，結尾自動發出 merge request 並釋出產出物，中間才交給代理執行（沙箱內跑 GPT-5.6 Luna，環境預裝 Python、Java、Kotlin、C#、TypeScript、Rust、Go 等 toolchain）。
    • 規模與成本：平台已累積超過 25,000 次任務、消耗逾 270 億 token，平均每次執行約 0.04 美元；iFood 表示選 GPT-5.6 Luna 是因為同級 checkpoint 中智慧、效率與執行速度的平衡最好。
    • 為判斷代理是否真的完成任務，iFood 在執行後用 Structured Outputs 要求輸出符合預先定義的契約，成功或失敗都能從回應結構中穩定辨識。
    • 第一個主要用戶是內部安全平台：它掃描 15,000 個儲存庫中的脆弱依賴並嘗試修補，改用遠端代理平台後，修補的準確率與解決的漏洞數量都成長超過一倍。

    • Agent Retrieval（原 Vector Search 2.0）新增托管擷取與 SearchDocuments，兩者均為 Public Preview：把 data store 指向 Cloud Storage 的檔案後，服務會自動解析、切段並用 Gemini Embedding 2 產生向量，開發者不必再自己寫 ingestion 管線。
