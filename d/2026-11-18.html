    Linked billing on the Claude Platform

    • Claude Platform 推出 beta 版連結計費（linked billing）：第三方平台不必再轉交 API 金鑰，終端客戶把自家 Claude 組織連結到平台，用量直接計入既有 Anthropic 承諾額度或按用量付費。
    • API 金鑰不再離開客戶組織，平台無須儲存、加密或輪替金鑰；由具 Owner、Admin 或 Billing 角色的 Console 使用者核准連結，可為每個平台設每月支出上限，並隨時在 Console 解除連結。
    • 平台端由 Anthropic 代管核准流程與帳單，省去自建計量與開票；可透過 Console 或 beta 的用量與成本分析 API 檢視各客戶請求數、token 用量與模型，也能逐次決定由平台或客戶付費。
    • 支援平台約 20 家，包括 Asana、ClickHouse、Harness、Higgsfield AI、Linear、Railway、Ramp、Tines 與 Warp；Linear 直言手動複製 API 金鑰本質上不安全。
    • 需注意請求是在平台所屬組織中執行，因此客戶組織的 IP 允許清單、加密金鑰與資料保留設定並不適用；第三方可在 Console 建立應用程式並依文件加入支援。

    Accelerating development for massive Git repositories

    Meet Another Build File Service (ABFS), Google's open-source content-addressable filesystem and build cache that cuts Android checkouts to &lt;8s and builds to ~2m.

    • Google 開源 ABFS，解決 Android 巨型程式碼庫的同步與建置瓶頸：Android 17 開源版有 1,084 個 Git 倉庫、162 萬個檔案，完整建置工作區佔 300 GB。
    • ABFS 以內容可定址貫穿全棧，含 Linux 核心模組 CASFS、使用者空間常駐程式與 gRPC 伺服器；CASFS 用 extended attributes 暴露 Git SHA，檔案內容等建置讀取時才延遲下載。
    • 實測取出時間從約 36 分鐘降到 8 秒內，完整建置從約 80 分鐘降到 2 分多鐘，共用快取在 CI 與開發者工作區間可重用最高 100% 的建置動作。
    • Ninja-go 以兩階段內容定址快取取代 Ninja 時間戳記判斷：先以指令、環境與已宣告輸入雜湊查找候選結果，再以讀取修補清單比對檔案系統現況，隱藏相依不同即不採用。
    • 單一 Cuttlefish 目標的建置圖有 192,249 個 Ninja 動作；開發者通常只改 1 至 10 個 Git 專案，卻可能在 64 核心機器上空轉約 80 分鐘重做 CI 已建置的內容。
