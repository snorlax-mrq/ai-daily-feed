    Measuring how AI agents handle everyday wet-lab science

    OpenAI introduces BioBasicsBench, a 100-task benchmark measuring how well AI agents interpret raw experimental data and handle everyday wet-lab science.

    • OpenAI 與酵素設計公司 Ligo 合推 BioBasicsBench：100 個任務全部來自科學家自己的實驗資料，測 agent 能不能讀懂凝膠與轉漬影像、菌落盤照片、顯微影像與 z-stack、流式細胞儀原始檔、FASTQ 等「日常濕實驗室」證據，並辨識實驗錯誤、判斷證據能否支持結論。
    • 任務覆蓋五個領域（蛋白質方法、影像與流式細胞、定量與分析、核酸方法、分子選殖），每題配專家撰寫的評分 rubric，經內部＋外部博士級科學家三層審查；答案按 rubric 分項給分，能區分「結論對」與「分析部分對」。
    • 成績（xhigh reasoning effort）：GPT‑6 Astra 66.7%、GPT‑6.1 Sol 62.0%，GPT‑5.6 Sol 只有 43.8%；評測共 7 個模型、37 組模型×推理設定、每題 5 次嘗試，合計 18,500 筆結果。
    • Astra 的進步在三處：辨識資料能／不能支持什麼（偵測染劑訊號重疊就拒絕下結論）、多模態細節（抓到陰性對照盤上的標籤寫錯抗生素）、保有實驗脈絡（認出顯微序列是 z-stack 而非細胞消失）。
    • 仍會犯的錯也很具體：讓既有假設壓過對照組證據（菌落 PCR 選錯 lane）、無視矛盾觀察（只記得「液泡較深」）、數菌落不準（鄰近分不開、漏數、把空瓊脂算進去，約高估 12%）。

    Agent Distraction

    Analysis of over 913,000 coding agent sessions reveals that 13% expose agents to inline TODO(b/...) comments. In 6% of encounters, agents act on these comments, with 83% being entirely unprompted by the developer. These

    • 以程式碼裡遺留的 TODO(b/…)／FIXME(b/…) 當客觀訊號（bug ticket 是唯一真相），分析數千名工程師、上億個 agent 步驟：13% 的讀檔 session 會撞見 bug 註解，6% 的遭遇觸發針對該 bug 的後續動作，其中 83% 完全自發、開發者沒要求。
    • 自發繞路有兩種樣態：41% 追的是已關閉的死胡同（32% 已修好／驗證完、9% 過時不修、2% 重複或受限 ticket）；57% 的 bug 還開著、agent 自行擴大範圍（61% 只查資料、39% 直接改程式碼）。
    • 用多路固定效應回歸控制開發者、程式庫複雜度、任務類型、模型等級、讀檔數等變數後，未經要求的 bug 繞路讓每個 session 平均多 70% 步驟、77% tokens、105% 等待時間（全數 p<0.0001）。
    • Google 的解法：派 agent 掃整個程式庫、回查 bug 與檔案歷史（有時跨數年），確認 TODO 與其意圖真的過時才送刪除建議；半年清掉數千條、人工審查接受率超過 95%。
    • 主張「agent-friendly codebase」不只熱路徑要健康：被遺忘的角落現在是對 agent 課稅，dead-todo 清理、presubmit 分析器、全庫掃描值得重新排進優先序。

    Introducing the New Auto and Auto Code Routers

    OpenRouter 官方部落格 · 公告

    • 新一代 Auto Router 打掉重練：不再只靠「任務類型」等粗糙訊號，改由快速決策模型一次評估 11 項請求特徵（任務種類、難度、是否剛切換、速度敏感度、需要視覺或 codebase 知識、更大模型／更多思考是否值得等），再疊上即時價格、供應商健康度與快取狀態，同時選出模型與 reasoning effort。
    • 實測依 benchmark 最多比舊版好 4 倍，p90 路由判斷 0.65 秒、快 3 倍（舊版 1.96 秒）；Auto Router 每月服務超過 10 萬人、2.5T tokens。
    • 新增 Auto Code（openrouter/auto-code）：專為編碼 harness 從零調校，起跳就用較高等級的編碼模型、更看重延遲、對失敗懲罰更重；五項 benchmark 成績與 Claude Opus 5.5 相當，但每任務成本省 74%。
    • 切換模型很節制以保護 prompt cache：beta 期間近九成 agent turns 停在同一模型，寧可先調 reasoning effort；同一錯誤反覆出現或編輯後測試失敗才提高換模型機率。beta 對比舊版：無效工具呼叫少 4 倍、代理回應被截斷少一半。
    • 治理相容：guardrails、零資料保留、供應商限制、允許／排除模型清單、BYOK 先收斂候選池，再在池內選成本最佳解；slug 不變（openrouter/auto），舊 auto-router 設定直接沿用。官方也坦承 router 仍打不贏單一最強前沿模型，定位是工作混雜、要控成本、不想追新模型的場景。
