一位小公司創辦人把研究、報價與排版交給名為 Aria 的 dot，自己留下策略判斷與最後審核。

Marina Petrova 是 Intentful 的執行長暨共同創辦人。團隊很小，替品牌把行銷做成人可以互動的東西。

產品包括會即時回答客戶問題的廣告，以及讓網站資訊可被 AI 讀取的工具；公司也做 AI 顧問與培訓。

客戶多在旅遊觀光業：目的地組織、飯店、餐廳、景點。客製提案是她談成生意的一部分：要同時說清楚做得到什麼、交付要付出什麼。

她的時間卻卡在研究、找檔案與排版提案上，策略工作被擠到最後。

dot 是 OpenAI 的常駐型 agent 產品（本站補充）。Aria 是她替自己的 dot 取的名字；原文說它會在她開口前就接手任務。

案例起點是一份網址表：Marina 要向一個觀光客戶提案，服務包涵蓋目的地數百家在地商家，得先篩出哪些網站進得了範圍。

條件由 Marina 給：網站要有可讀的 sitemap，頁數不超過 3,000。Aria 先篩掉不合格的網站，納入與否仍由 Marina 定；原文提到她給的清單約 300 份 sitemap。

（編輯觀點：把標準寫成「可讀 sitemap、3,000 頁以內」這種規格，才是 agent 接得住判斷的原因。）

報價與排版：兩段最花時間的工作

價格不是憑感覺。Aria 透過 ChatGPT 外掛讀 Intentful 放在 HubSpot 的銷售資料，包含過去的合作與討論。

它整理出舊約的報價，也帶進公司對隔年規劃的脈絡。

接著兩人一起建模型：頁數決定價格級距，舊約再校正價格。原文強調這是「一起」完成的客製模型。

寫提案時，Aria 知道要用 Google Drive 裡的 Intentful 範本；Marina 也能指定舊提案當參考，讓草稿一開始就對上風格。

產出是一頁式提案，最後由她審閱與編輯。她的說法是：只需講清楚要放什麼，不必再花一小時想版面。

它會自己發現你沒查的事，也守住你畫的線

Aria 也會看到她沒想到要查的地方。沿用舊報價時，它發現續約日期和她記憶中的時點對不上，標出落差，並在新稿裡拿掉那個日期。

除了提案，她也用 Aria 把事情講過一遍：找對話、查客戶在 CRM 的歷史、在 Asana 開任務與指派。

草稿要改，她直接在 Google Docs 留下評論；長文件請 Aria 開建議模式，逐處比對改了什麼。

訊息面靠 Gmail 與 Slack 外掛：Aria 挑出需要她回覆的訊息；她離線時，它抓到一通當天早上的通話邀約並通知她。

會議簡報被同事加了兩張投影片，它自己更新講者備註再回報。她則常用電話在路上交代事情。

她備一堂教 agent 的 AI 101 課時，直接用 Aria 做教材。流程本身就是教材：交出一件真任務、給足脈絡、質疑結果、掌握最後放行。

課後也真的跑過一次：學員索取訓練檔，她問 Aria，檔案已經送出。

另一場 50 人的課程，Aria 發現軟體異常讓錄影打不開，先標出存取問題，再提議修好才分享連結。

邊界寫得明白：她決定 Aria 能讀哪些資訊，外寄郵件一律由她審。

（編輯觀點：這是單一客戶、單一使用者的敘述；原文沒有失敗案例、沒有導入成本，也沒有其他員工的視角。）

帶走三件事

條件寫得出來，才交得出去。規格含糊，agent 只能猜。

dot 的價值在串接。網址表、HubSpot、Drive 範本接起來，才省下幾天。

審核權別外包。存取範圍與外寄郵件留給人，才敢讓它自己跑。
