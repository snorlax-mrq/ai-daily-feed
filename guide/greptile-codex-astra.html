30 秒版本

Greptile 做的是「帶著整個 codebase 脈絡」審查並測試程式碼變更的 AI agent。這篇 OpenAI 客戶案例記錄它的兩個做法與一個展望：用 GPT-6 Astra 的 computer use，不只讀 code，還替 PR 起開發伺服器、把瀏覽器縮成 iPhone 視窗、模擬使用者操作，抓出只有執行才看得到的 bug；把 Knowledge Base 透過 MCP server 開給 Codex，讓 AI 寫出符合客戶既有模式的程式——據 Gupta 說法，數千客戶已接上，並以「AI 程式碼被 revert 的頻率」量測成效；執行長 Daksh Gupta 認為對 Greptile 而言，唯一真正的瓶頸是把想法變成軟體的速度，將 Ultrafast 視為加速開發的方向。

  • 有些 bug 讀不出來：按鈕在 iPhone 視窗上消失，要真的跑起來、看畫面才抓得到。
  • 脈絡是可量測的投資：Knowledge Base 經 MCP 餵給 Codex，以 revert 率驗證「有脈絡，較少被退回」。
  • 模型越強、攻防同時加速：Daybreak 要讓「即使新創」也能有比攻擊者更細膩的防禦。

為什麼只讀 code 不夠：把「執行」交給 computer use

Greptile 的 agent 帶著整個 codebase 的脈絡，審查並測試程式碼變更；共同創辦人兼執行長 Daksh Gupta 的使命宣言是 「We are in the business of reducing bugs and making the world's software more reliable」。原文把 PR 驗證拆成四件事：程式邏輯正確、做了開發者想做的事、安全、不破壞既有功能——而其中一部分，非得真的把應用跑起來不可，光讀 code 未必看得出問題。

具體例子：一個按鈕，在 iPhone 上檢視網站時會消失。有 GPT-6 Astra 的 computer use，Greptile 可以替這個 PR 起一台開發伺服器、把瀏覽器縮成 iPhone 尺寸的 viewport、模擬使用者在應用裡走一遍——模型靠視覺理解檢查畫面、抓出那顆消失的按鈕。Gupta 的對比很直接：「A QA firm testing all of your changes is just impractically slow considering how fast we're able to ship code with these models.」——人工 QA 跟不上模型時代的出貨速度，所以這類測試得以自動化到 scale。

Codex＋Knowledge Base：讓 AI 寫出「像這家公司」的程式

Greptile 的 Knowledge Base 為公司 codebase 建索引，把「它怎麼運作」文件化成人與 agent 都讀得懂的形式，再透過 MCP（Model Context Protocol）server 開給 Codex。效果是 Codex 寫出的程式會遵循客戶的既有模式；據 Gupta 說法，已有數千名客戶把 Codex 連上這套知識庫。

成效怎麼量？團隊追蹤 AI 產生程式碼被 revert 的頻率：「When we provide agents with context, fewer reverts happen and customers save time and save inference.」——有脈絡的 agent 較少被退回，省下的時間與 inference 成本可以轉投新工作，而不是重做同樣的修改。Greptile 自己也是重度用戶：「We are massive users of Codex」，每個職能都有大量用量，工程部門尤甚。

著墨短但值得留意：Daybreak 與 Ultrafast

Daybreak：Gupta 觀察到，更強的模型同時讓攻擊者更容易利用應用程式的漏洞，連過去不是典型目標的公司都暴露在風險中。他的說法：「We want to make it very easy for even a startup to secure their systems」；而 Daybreak 能以「非常安全」的方式做到這件事，讓客戶的防禦機制比對手的攻擊機制更細膩。要注意的是：原文對 Daybreak 本身沒有產品細節，收錄文字能驗證的就到這裡。

Ultrafast：Gupta 認為對 Greptile 來說，唯一真正的瓶頸是把想法變成可用軟體的速度——模型智慧對許多任務已經足夠，所以他視 Ultrafast 為加速開發的方法。長期目標：讓修改與發布關鍵企業軟體，變得像發布 side project 一樣簡單，OpenAI 則協助 Greptile 建構所需的驗證。同樣地，原文未展開 Ultrafast 的技術細節，這裡只忠實轉述其定位。

帶走三件事

Code review 的下一站是應用測試。邏輯、意圖、安全、回歸四關之中，有些非跑起來不可，這部分得以用 computer use 自動化——iPhone 視窗上消失的按鈕，是典型只有執行才找得到的 bug。

給 agent 脈絡，是可以量測的投資。Greptile 挑了 revert 率當指標：有 Knowledge Base 的 agent 改動較少被退回——脈絡的投資報酬，反映在省下的時間與 inference 成本上（編輯推論）。

強模型同時放大攻與防。更強的模型同時讓測試與攻擊都變更容易（編輯推論：防禦自動化與測試自動化是同一枚硬幣的兩面）；Greptile 把「讓防禦比攻擊更細膩」寫進說法。
