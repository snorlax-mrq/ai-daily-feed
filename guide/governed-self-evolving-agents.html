Project Chrysalis：自我進化的 SRE 代理，每個補丁都要過四道閘

30 秒版本

Google Cloud 研究參考架構 Project Chrysalis 把三項研究突破組成一套跑在 Gemini 平台與 ADK 上的自我進化 SRE 代理：Dream-RSI 把生產流量軌跡送進 BigQuery 離線重放數百組候選政策、APEX 把 agent 進化拆到三個受治理的時間尺度、AgentEvolver 用逐步 Shapley 歸因分辨哪一步救了服務、哪一步造成附帶損害。模擬 Black Friday 快取雪崩中，首次緩解從 15–45 分鐘縮到 1.8 秒、HTTP 5xx 降到 0.0%；而每個自主動作都被四道防禦縱深閘門以密碼學方式約束，永久變更更需 SRE 明確簽核。

  • 傳統 agent 部署後即凍結：固定 system prompt＋預註冊工具，遇新型瓶頸只能等人工。
  • 三支柱對應「SRE 三難」：探索安全、結構可變性、多步功勞分配，各解一環。
  • 自我進化不是黑箱：Model Armor、KMS 簽章、OPA 護欄、雙人複核，層層把關。

問題：事故現場不需要建議，需要緩解

企業雲平台要服務數百萬並發使用者，緊耦合的微服務會產生靜態 runbook 與閾值告警都預料不到的級聯故障。在 Black Friday 快閃特賣這種高速度事件裡，SRE 面對的是不留情面的現實：幾秒內診斷嘈雜的分散式遙測，否則承受每分鐘數百萬美元的級聯中斷。

生成式 AI copilot 已加速寫碼與日誌摘要，但 AI 代理始終難以可靠地修復線上生產事故。原文的例子很傳神：正在對抗連線池耗盡（connection pool starvation）的值班工程師，不需要一個提供「故障排查建議」或提出未經驗證 PR 的 agent——他需要的是一個受治理、能自我進化的系統。傳統 agent 部署後即凍結（固定 system prompt＋預註冊工具），遇到新型基礎設施瓶頸便束手無策；自我進化架構則在執行期合成情境專屬的緩解工具、為每次介入評分其遙測影響、並把驗證過的護欄編纂下來留給未來的事故——進化的依據必須是「什麼有效、什麼失敗」的實證。

三根研究支柱

原文把自我進化雲端代理定位為應用研究的活躍領域，核心難題是 SRE 三難（SRE Trilemma）：平衡探索安全、結構可變性、多步功勞分配——三個支柱各解一環。

不當黑箱：四道防禦縱深閘門

自我進化最可怕的想像，是不受控的黑箱。原文明言這套架構並非無約束的黑箱：每個自主動作都被 Google Cloud 的防禦縱深安全棧以密碼學方式框限；且每個合成的補丁、蒸餾的記憶與拓撲更新，都必須依序通過四道驗證邊界——一條不間斷的監管鏈（chain of custody）。

01入口消毒

Model Armor：遙測進來先過安檢

對送進 agent 的遙測資料消毒，防範提示注入（prompt injection）與資料外洩——事故期間滿天飛的日誌與告警，正是夾帶惡意指令的高風險通道。

02補丁簽章

Cloud KMS＋Binary Authorization：沒簽章的代碼掛不上

以 Cloud Key Management Service 與 Binary Authorization 中介層，為 agent 合成的補丁做密碼學簽署，阻擋未經驗證的代碼被掛載執行。

03政策護欄

OPA Policy Controller：SLA 紅線寫進政策

以 Open Policy Agent 政策強制嚴格的 SLA 護欄，防止 agent自我造成的服務中斷——進化不能以犧牲可用性為代價。

04雙人複核

Dual-Custody HITL：永久變更需 SRE 明確簽核

雙重保管人的人機協同治理（Human-in-the-Loop）：對 agent 層級（hierarchy）的任何永久變更，都必須有 SRE 的明確簽核才放行。

實測結果怎麼讀

在對 Black Friday 快取雪崩（cache-stampede）工作負載的自動化評估中，這套受治理架構對比人工分診與靜態建議式 copilot 交出的數字：首次緩解時間（time-to-first-mitigation）從 15–45 分鐘壓到 1.8 秒；HTTP 5xx 錯誤率從 72.7%–80.0% 的基準降到 0.0%；P99 延遲從 519.8 ms 降到 18.2 ms；並在 BigQuery 上以約 0.5 ms 評估了 400 組反事實流量政策。

讀這組數字要記住脈絡：它出自模擬示範（demo simulation）的自動化評估，而非真實生產環境的事故；原文的定位是「研究參考架構」，文末提供參考實作與 Google Cloud 文件供自行驗證。它的價值不在「1.8 秒」這個絕對值，而在於展示了一個反直覺的組合：治理成本不必以犧牲反應速度為代價。

帶走三件事

自我進化的前提是可歸因。沒有 step 級的 Shapley 歸因，agent 只知道「最後修好了」，不知道哪一步立功、哪一步闖禍——那樣的進化只是在放大運氣。

自主性與治理是一體設計，不是事後上鎖。四道閘門沿著補丁的生命週期排列（入口消毒→簽章→政策→雙人複核），這讓「放手讓 agent 動手」成為可以簽字的決策。

先在離線世界演練，再到線上動手。把生產流量軌跡丟進 BigQuery 重放、0.5 ms 掃 400 組政策——危險參數不必在生產環境裡試錯，這是 self-evolving 不等於 reckless 的關鍵。
