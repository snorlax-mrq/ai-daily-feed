OpenAI 沒有再造一套 CRM，而是把銷售每天要跑的六段工作接進同一個對話，再讓常駐 agent 在你不在線時接手。

原文把目標寫成三句：讓業務更懂客戶、少花時間在雜事上、成交更多筆。

開場的問題清單很直白：該追哪些帳戶、買家還需要什麼才能往前走、哪些交易該盯、為什麼。

答案散在同事、開發名單的工具、客戶通話與 CRM 裡。原文的說法是收在一起，團隊才挪得出時間做判斷。

Sales plugin 是 OpenAI 自己做的那一個，賣的是現成工作流：挑該追的帳戶、準備通話、起草跟進。

它與夥伴外掛並列安裝，原文要團隊自己挑「符合你銷售流程」的那幾個，不是全部打開。

原文說它內建給業務用的專門 skill（技能），但沒列名稱，也沒給使用率或成交成效。

原文稱它是「每位業務的起點」：先給一套每天用得上的現成流程，擴充再說。

這些工作流跑幾步、哪一步要人核准，原文也沒寫，等於留給各團隊自己定。

六類工作，30 多個外掛

夥伴外掛照銷售工作的段落分成六類，原文逐類點名工具；這批是新增與強化並計的 30 多個。

外掛的邊界也寫清楚了：能用哪些、能不能用，取決於方案、地區與工作區設定三件事。

四個用法，加一個常駐 agent

原文給四個場景，收尾都是草稿、清單或待你審的建議：名單、說帖、跟進、風險。

四段場景各自獨立，串起來的是同一份客戶脈絡，不是原文給的先後流程。

小標寫的是「每個銷售團隊都用得到」，但四段都沒給省下多少時間、也沒給覆核比例。

第四個場景多了一個角色：dot。它是 ChatGPT 裡的常駐 agent，用同一批外掛與同一份客戶脈絡。

原文說它可以做三件事：備會議簡報、追交易更新、把變化與建議的下一步帶回來給你審。

例子是請 dot 每天早上查一筆交易、標出要處理的變化，再備好簡報或跟進序列。

（編輯推論：前景是 Sales plugin 帶著人跑，背景是 dot 把變化推回來，兩邊靠同一份脈絡接起來。）

導入走管理員：Business 與 Enterprise 進 Admin Console 選工作區、開 Plugins，開放成員安裝或預設安裝。

原文另提醒管理員先審查所需 app 與它們能執行的動作；成員再依提示完成帳號連結。

原文的示範段落提供 Sales 上線示範與 HubSpot 夥伴示範等影片。

沒給的部分同樣乾脆：價格、上線國家清單與客戶成效數字全無，案例段落也只有畫面與導語。

原文收尾只承諾會繼續擴充這批外掛生態，把更多銷售工作搬進 ChatGPT；時程與範圍未寫。

帶走三件事

外掛是接口，脈絡才是產品。再多外掛都共用同一份客戶脈絡，這才是賣點。

先問方案與地區，再看清單。清單再長，工作區沒開、地區沒到就用不了。

dot 把問答變成待審草稿。它跑背景、你審下一步，責任還在你手上。
