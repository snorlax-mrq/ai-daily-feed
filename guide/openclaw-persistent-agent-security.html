常駐 agent 資安：gateway 算可信，agent 算不可信

導讀

原文：OpenAI 官方工程部落格，說明全公司部署 OpenClaw 常駐 agent 時採用的隔離與審查控制——第一方部署經驗，成效敘述無第三方驗證

OpenAI Developers Blog（Kevin S Lin）·2026-11-12 發布·2026-11-12 收錄· 閱讀官方原文

500+原文末段稱 pilot 後全公司有超過 500 個 agent 在背景自主執行；前段另稱「數百個」OpenClaw agent
4 道沙箱控制面：network、workspace、process、secrets，全由靜態設定強制
2 份設定requirements.toml 只管「有哪些選項可用」，config.toml 才是實際設定
1 個 agent 1 個身分各綁一個 ChatGPT Service Account，推論憑證與使用者分開，可單獨關掉推論

威脅從內部來。OpenAI 的解法是先切信任邊界：gateway 算可信程式碼，agent 一律算不可信，再往外疊沙箱、模型審查與獨立身分。

原文開場把兩種 agent 對比得很清楚：一般 codex session 有固定目標、有人盯；常駐 agent 24/7 在跑、範圍廣，還能未經使用者輸入就主動動手。

傳統軟體的假設是設定與程式碼具決定性，威脅多半來自外部攻擊者。常駐 agent 會改自己的設定，也會為達目標寫任意程式碼。

所以攻擊面翻轉成原文那句話：攻擊從內部來——agent 出現 misaligned（不對齊）動作時，沒有外部入侵者可以怪。

這個翻轉決定後面所有設計：要防的主要不是入侵者，而是「會自己寫程式的執行者」。

切開邊界：把設定者與被設定者分開放

做法是把可信的決定性邏輯與不可信的 LLM 執行隔開。可信的是 networking、identity、sandboxing 這類靜態程式。

OpenAI 在開源專案實作 remote harness execution，讓 OpenClaw Gateway 跑在獨立容器，在 OpenAI 的部署裡甚至獨立叢集，與 agent harness 分離。

分開之後，負責設定 agent 的 gateway 可以當可信程式碼對待，力氣集中在一件事：把 agent 工作負載當不可信程式碼沙箱起來。

沙箱不是一個開關，是四個面：網路、工作區、行程、secret。原文各自的限縮方式與設定證據如下表。

控制面原文做法設定檔證據（原文節錄）
network組織管理的 allowlist，並對受限端點明示 denymanaged_allowed_domains_only=true 擋使用者自行擴充；allowed 僅 github.com、api.github.com、codeload.github.com（原文註：這是示例，要換成該工作負載實際需要的主機）；denied 含 pastebin.com、webhook.site、169.254.169.254
workspace只允許寫入 agent 工作目錄:minimal 唯讀、openclaw-workspaces 可寫、read-only 唯讀、.ssh 設 deny

（編輯推論：這些都是現成的資料外送與取憑證通道，清單把 agent 當成可能的 exfiltration 管道，而不只是會被騙的受害者；原文未解釋選材依據。）

兩份設定檔分工也值得學：requirements.toml 限制可用選項，config.toml 才是實際設定；danger-full-access 模式直接從可用範圍移除。

搜尋只准 cached 模式，走 OpenAI 自家索引；apps 預設關閉，破壞性與 open-world 操作也預設停用。

原文自己點明這層的性質：全部是靜態控制，靠的是傳統決定性程式碼。

靜態控制之外：會隨算力變強的防線

靜態控制的極限是：模型變強，能繞的路徑也變多。原文因此補上「會隨算力擴展」的防線——另一個模型。

Auto-review 讓第二個 agent 監看並核准主 agent 的動作。理由寫得很直白：凡事都要人核，人會被訓練成照單按同意。

用 LLM 當過濾器，把人的注意力留給高價值核准。OpenClaw 與 Codex 都原生支援，OpenAI 在其 OpenClaw 部署裡對所有 agent 動作強制啟用。

身分的關鍵字是「分開」：agent 有自己的身分，才能回答某個動作是 agent 還是使用者發起，也才能單獨關掉它的推論。

原文也把兩件常混用的東西分清：agent identity 不同於 service account（給 bot 的獨立 API 存取），兩者要一起用。

規格仍在成形：WAG 給 agent 自己的資源授權，XAA 走 OAuth 委派，讓 agent 代表使用者行動。

在 OpenAI，每個 agent 的身分綁一個 ChatGPT Service Account，因此有自己的推論憑證，團隊也能替它接自訂外掛。

可觀測性那節最絕對：全量記錄，但因為 agent turn 可能含敏感內容，日誌鎖住，只有安全團隊少數人能看。

（編輯觀點：這幾層裡只有 auto-review 會隨模型變強而變強；沙箱擋的是已知路徑，日誌只能事後追。）

原文最後把這套控制產品化：dev day 發表的 OpenClaw Enterprise 是開源、廠商中立的 agent control plane，用 standard codex preset 起 agent 就自帶多數防護。

但仍在 pilot 階段，原文說目標是年底到 1.0；也自承常駐 agent 還在採用曲線開端，缺乏既定最佳實務。

pilot 的成效是生產力與採用率大幅跳升，技術與非技術團隊都有（OpenAI 自報，原文未給數字）。

帶走三件事

先切信任邊界，再談沙箱。gateway 可信、agent 不可信，隔離才有依據。

靜態與模型兩層不可互替。沙箱擋已知路徑，審查才隨能力擴展。

身分與日誌是追責的前提。沒有獨立身分，稽核分不出動作是誰做的。
