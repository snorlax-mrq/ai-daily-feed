Gemini 4 Carbon：長時程 agent 專用模型，與 /swarm 的分工

導讀

原文：〈Gemini 4 Carbon is now available〉——模型發布公告（Google 部落格，DeepMind 同日轉載）

Google Blog（AI）·2026-11-10 發布·2026-11-11 收錄· 閱讀官方原文

3 個榜單第一CursorBench 4.0、Perplexity WANDR、Zapier AutomationBench
低 2 倍以上每任務成本相對「次佳外部模型」，Google 自報
兩週前先給 Fairwind Program 的資安防禦者使用，才對外開放
/swarmAntigravity 預覽功能：一個 prompt 展開成可追蹤的 agent 團隊

Google 這次不是說「更強」，而是說「換一種用法」：用更多 token 換更深推理與更長驗證迴圈。

Carbon 的定位寫得很明確：資安能力，加上長時程 agentic 工作流。

它與 Gemini 4 Argon 並存。Google 說 Argon 仍適合大多數軟體工程與知識工作，Carbon 留給會逼近模型極限的任務。

具體例子：多步驟的複雜 coding 與除錯、開放式的科學研究與探索——共同點是沒有明確終點。

「長時程」的具體意思：任務會跑很多步、需要來回驗證，中途失敗一次就整段重來。

代價講得也直白：Carbon 會燒更多 token，換取徹底探索、深度推理與多輪驗證。

榜單與成本是同一句話的兩半

原文強調的不只是排名，而是「排名＋每任務成本」的組合：在三個外部 benchmark 第一，成本是次佳外部模型的二分之一以下。

這對 agent 特別關鍵：長時程任務本來就會放大單次推論的差距。

三個榜單分屬不同工具：程式編輯器、搜尋型研究、自動化流程，共同點是測真實工作流而非實驗室題庫。

取得路徑分成兩條：開發者走付費 API，消費者與訂閱者走 AI Studio 與 Antigravity。

Fairwind Program 的先導期值得注意：先讓防禦方試用，再全面開放，是 Google 對高風險能力的慣例。

開發者版本另補了一句：Carbon 有更強的對齊與「任務完成度」，這對跑很久的 agent 比單題正確率更關鍵。

家族順序也要看清楚：Carbon 接在 Argon 之後推出，不是取代關係，而是按任務難度分層。

對 agent 開發者來說，這種分層意味著一件事：選型要看任務長度，不是看單題分數。

公司若已在用 Argon，Carbon 的導入成本主要是重調 prompt 與驗證迴圈，而非重寫流程。

（編輯觀點：benchmark 第一不等於你的工作流第一；長時程任務的變異大，還是得自己抽樣測。）

/swarm 才是這篇最值得看的部分

它把單一 prompt 變成一個可即時追蹤的 agent 團隊，並要求開發者主動分配角色。

原文的建議是：架構設計、協調、稽核這類需要最深推理的位子交給 Carbon，其餘可留給較輕的模型。

這是把「模型選型」從一次性決策，變成任務內部的動態安排；也是 agent 工程最近一年的共同方向。

實務上要注意的是可觀測性：一個 prompt 展開成多個 agent 後，出錯時得知道是哪個角色壞的。

原文只說可在 Antigravity 中即時追蹤，尚未提供團隊規模或成本控制的細節。

（編輯觀點：模型分工正在變成預設做法——「一顆模型打全部」的時代，廠商自己也不這樣用了。）

帶走三件事

別急著全換。Argon 仍覆蓋多數工作，Carbon 是攻堅用。

成本要按任務算。單價高不等於每任務貴，長任務會放大差距。

多 agent 已成產品功能。/swarm 把「派角色」變成介面操作。
