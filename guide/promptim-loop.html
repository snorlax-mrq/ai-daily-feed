Prompt 最佳化：讓評估分數來改提示詞

實驗性原文自稱 experimental library、開源釋出的「第一次嘗試」，範圍只到單一 prompt
4 件輸入初始 prompt、資料集、自訂評估器，加上可選的人類回饋；前三件是必要項
dev／train／test可選的資料切分；基線與每輪比較都在 dev（未切分時用整份）上算，改稿例子取自 train
pip install promptim開源函式庫，接 LangSmith 管資料集、prompt、結果追蹤與選配的人工標註

把調 prompt 變成有分數的迴圈：人出資料集與評估器，改稿交給 metaprompt 提案，留不留看 dev 分數。

原文先把地基講清楚：這是「評估驅動開發」。先建一份輸入資料集（可選配期望輸出），再定義幾個評估指標。

之後每次改動 prompt，就整份跑一遍、逐筆打分，確認在進步，至少不要退步。原文點名 LangSmith 這類工具負責資料集整理與評估。

Promptim 把迴圈裡「動手改」這一步自動化：改稿由程式提案，再由同一套評估打分決定去留。原文承認 DSPy 早就在做這件事。

原文給三個動機：省下手工調詞的工程時間；替「介於藝術與科學之間」的調詞帶來嚴謹；以及換模型時少改一次 prompt。

第三點值得展開。不同模型要不同提示策略，換供應商不是改個 URL 就好；評估與模型無關，prompt 才有關，力氣放在 eval 上更划算。

這套設計的紀律在最後一格：只有 dev 分數進步，新 prompt 才留下。留哪一版由量測決定，不由提案的語氣決定。

改稿的動作範圍也窄：metaprompt 只重寫 prompt 的文字，不動模型、不動工具、也不動資料集。這是它與「直接換一顆更強的模型」的差別。

（編輯觀點：把「留不留」寫成硬規則，比再多的提示詞技巧都實在——它讓最佳化有可回滾的版本，不是一次口頭承諾。）

人只出三樣東西，外加一段回饋

原文的輸入清單很短：LangSmith 裡的一份資料集、LangSmith 裡的一個 prompt，加上本地定義的評估器。

輸入放在哪裡／由誰提供原文限定語
初始 promptLangSmith 的 Prompt Hub，事後也回存這裡必填；只最佳化這一個 prompt
資料集LangSmith，含可選的期望輸出必填；可再切 train／dev／test
評估器本地定義，不必進 LangSmith必填；決定「什麼叫好」
人類回饋LangSmith 的標註佇列（Annotation Queues）選配；沒有好自動指標時才用

表格為本站整理。原文敘述三項必填與一項選配，未給此表；「不必進 LangSmith」指評估器在本地定義。

評估器是重心：它定義什麼叫好，也決定 metaprompt 收到什麼訊號——原文餵進去的是輸入、輸出、期望輸出與分數。

沒有好指標時，人工回饋是替代路徑。原文說這適合自動指標不夠用、或想調到指標管不到的地方，走的是標註佇列。

切分也是選配，但原文把它寫進建議做法：基線與每輪比較看 dev，改稿素材看 train，試探與驗收看的是不同批例子。

原文寫的是跑過 train（或整份）裡的所有例子，不是抽樣；評估器用的是使用者自訂、本地定義的那一份。

不是萬靈丹：三點與 DSPy 分道

原文先自我設限：這是第一個嘗試、定位 experimental，只做「改寫單一 prompt」這一件事。評估標準仍得你自己寫。

對照點promptimDSPy（原文歸述）
範圍單一 prompt；原文認為目前比較可解整個「複合 AI 系統」
人的位置留在迴圈裡：標註佇列、Prompt Hub 事後複核、結果進 LangSmith原文稱「把人拿掉得多一些」
手段只改寫 prompt，並力求把這件事做好範圍更廣，含 finetuning、few-shot prompting

表格為本站整理。三點對照取自原文「It's worth comparing our approach to theirs」後三段；原文同時稱 DSPy 是這個領域的領先工具。

原文的結論是兩者解不同問題，不是同一題的兩個名次。範圍小是刻意的取捨，換來的是單一 prompt 這件事比較做得到。

人的位置也寫得直白：至少留一個人做 sanity check，最後看一眼結果。這是它把 prompt 存回 Prompt Hub 的理由，事後翻得到改了什麼。

接下來原文列四個方向：推進動態 few-shot、接進 LangSmith 介面、加更多最佳化方法、整張 LangGraph 圖的最佳化（理想上與 DSPy 整合）。

安裝是一行 pip install promptim，另有 YouTube 走查影片，回饋走 GitHub 與 Twitter。

（編輯觀點：兩者的分歧與其說是技術，不如說是對人的假設——一邊先假設人可以退場，一邊先假設人得留著。整篇讀下來，它是一把先磨小的刀，不是產線。）

帶走三件事

評估器才是資產。prompt 會換、模型會換，判分標準留下來。

留版規則比提案重要。進步才換、否則退回，最佳化才有回頭路。

範圍小是設計，不是缺點。單一 prompt 先做，別當成整座系統的自動調校。
