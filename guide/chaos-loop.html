混沌迴圈：20 億次請求只 60 次錯誤

導讀

原文：Anthropic 工程部落格（作者 Vivek Nair，Docs 團隊），記述如何在 staging 上架「混沌迴圈」，讓 Claude 連跑兩週壓測並修掉倒下的地方，把單節點 PoC 撐到上線規模。

Claude（claude.dev Blog）·2026-11-17 發布·2026-11-19 收錄· 閱讀官方原文

超過 460 萬份9 月 22 日止建立的 Docs 文件數；9 月 16 日上線，首批 100 萬份約 30 小時出現
20 億次請求上線到 9 月 22 日之間的請求總量
60 次伺服器錯誤20 億次請求中的伺服器錯誤數；同期間未發生需要回滾的故障
約 50 個 pod整個 Docs 服務的記憶體優化 pod 數；壓測前的上線估計超過 500 個

上線前 3 週，Docs 還只是單節點上的 PoC；團隊讓 Claude 在 staging 連跑兩週混沌迴圈，把會倒的地方逐一修掉，換來一個沒回滾過的上線。

三週前，它只是單機上的一個 PoC

Claude Docs 是編輯器：你、同事與 Claude 可以同時在同一份文件裡讀寫與留言，任何一個 Claude session 都能直接開進來。

上線前 3 週，整個服務跑在單一節點，幾千名 Anthropic 內部人員在用；團隊自己估，上線頭幾天就會出現數百萬份文件。

這種規模測不出上線風險，也沒有真實流量可測。9 月 4 日，作者讓 Claude 開一個常駐 session，驅動鏡像 production 的 staging 叢集，每天灌超過 100 萬份合成文件。

迴圈本身很樸素：選情境、跑 harness、讀遙測、提修法、部署到 staging、再跑一次。session 當協調者，把工作丟給 sub-agents，最忙一週同時約 11 個、峰值 30 個。

協調者還會透過 Slack MCP 去問 Anthropic 內部的 Claude Tag（beta），讓別隊跑過的代理先替這套擴充方案挑坑。

情境刻意偏執：單日新增 1,000 萬份文件；22,000 條連線同時重連；熱門文件湧入數百名檢視者時伺服器被殺、資料庫同時停頓。

開跑前先劃紅線：改資料庫 schema、key 布局、文件如何儲存與 materialize 算難回復，必須停下問人。Claude 通常附建議，作者多半照准。

兩個不變量全程有效，且跨多次 compaction 沒被忘記：文件要幾乎瞬間開啟，伺服器 ack 過的編輯必須還在。

讓服務對模型可讀，迴圈才收斂

遙測細到每條資料庫查詢都報名稱、掃描列數與回傳列數，Claude 才看得出查詢壞在哪並改寫。人手寫遙測很瑣碎，多半等出事才補；這回是邊跑邊補。

原文叫它「診斷迴圈」：Claude 每輪讀遙測，順手補上它認為缺的訊號，不只被動看既有儀表板。

同一輪 harness 也判斷改動好不好回復；好回復就讓 Claude 自己上 staging 重跑，不好的才回到人手上。

記憶體是最好的例子：一份大文件在 pod 上吃掉約 3 GB；Claude 先縮小自家快取，下一輪卻顯示記憶體其實在依賴套件裡，它把改動撤回。

再細切 profiling，發現每次按鍵都把文件複製進好幾個結構、各多幾 MB；改成 copy-on-write 共用一份參照，三天內壓到約 180 MB。

容量估計跟著變：上線所需 pod 從超過 500 個降到約 50 個。選 Rust、砍依賴是同一思路——數字要能追回自己寫的程式碼。

團隊刻意避開 GC：GC 的記憶體與延遲按它自己的時程漂移，訊號變吵就難歸因到某段程式碼；Rust 讓記憶體全在自家結構裡。

作者也承認取捨：Rust 不好寫，幾年前這會是決定性缺點，現在 Claude 寫得動；但這是他從 Go 轉來的體感，原文沒做兩語言對照。

上線週、時機與這筆帳

九月對 production 部署 629 次，一次都沒回滾。上線週的體感是「熟悉」：十個演練情境有七個真的在 prod 發生。

修補早在 runtime flag 後面，壓力一來多半只是翻 flag，而不是臨場改程式。

作者說幾個月前這招行不通：舊模型讀遙測沒問題，但跑到一、二十輪就忘記在優化什麼，他得一再重述目標——內部稱之為 goal drift。

新模型能長時間守著同一目標，是迴圈成立的前提，不只是附帶好處。他用的是內部研究模型，約等同 Claude Fable 5.2。

成本約 12.5 萬美元，多數花在讀遙測、寫提案、生成修補與審查程式。其中一部分是規模稅：只有這個量級才需要的基礎設施，本身也要推論才想得清楚。

他估重來一次可只花一半；小服務兩週推估 3,000–10,000 美元，兩年前同等工作量則是他「猜」約需一組工程師半年——後者原文明說沒實跑。

帶走三件事

先修訊號，再修程式。遙測吵，迴圈就只是猜；避開 GC 是為了可歸因。

把不可回復的決策留給人。schema、key 布局、儲存格式，其餘放給模型連跑。

零回滾是自報成果，不是保證。換服務前先問自己的遙測夠不夠細。
