1 個模型Mistral Large 4，代號 Le Chonk；主打程式碼、防禦性資安與文件推理
3 種形態代理負責調查與動手、工作流負責編排與核准、App 是員工的入口
3 種部署雲端、自家 VPC、地端，也可混搭；模型與平台一起搬
至少 7 組客戶與夥伴原文列舉 ABANCA、Accenture、Alten、BNP Paribas、Capgemini、CMA CGM、TCS 等，已在生產環境（原文為 including，未窮盡）

這次賣的不是模型分數，而是換模型時不用重寫的那一層。

原文的定位句很直白：Le Chonk 提供腦力，Studio 負責讓它在業務裡動起來。

Studio 的起點是模型，透過連接器與 MCP 伺服器接上企業資料與系統，再往上長出代理、工作流與 App。

執行由平台托管，團隊事後能回看發生什麼——這句話是整篇產品說明的主軸。

至於 Le Chonk 本身，原文只給三個方向（程式碼、防禦性資安、文件推理）與「開放模型」四字；第三點原文寫的是文件與業務任務推理，沒有分數、參數或授權條款。

（編輯觀點：對採購方來說，「開放」現在至少有三種意思——權重可下載、可自架、授權允許商用；原文沒說是哪一種。）

三種形態，各管業務流程的一段

形態原文定義這次新增
代理調查情況並採取行動代管代理：skills 記流程、sandbox 跑程式、subagents 分工、hooks 插自訂邏輯
工作流協調執行與核准中斷可續跑、企業系統事件觸發、可檢視的視覺化流程圖
App讓員工使用這些系統托管、驗證、存取控制，可用預先核准的可重用元件

三者共用同一套基礎設施，這是重點：資料、連接器與權限只接一次，三種形態都吃得到。

工作流把「固定規則、代理推理、人來決定」三種步驟寫在同一張圖上，哪裡要蓋章一目了然。

（編輯觀點：企業真正卡住的從來不是模型能不能做，而是誰簽核、出錯誰負責——簽核點放進工作流是對的方向。）

原文舉例：產品營運用工作流辨識 bug 與功能需求，再依規則分派給對的團隊。

工作流中斷可續跑這點，實務上比看起來重要：長流程卡在人等簽核時，重跑一次等於把所有副作用再做一遍。

能上線的差別，在可觀測性與評測

每次執行都留 OpenTelemetry trace：模型呼叫、工具使用、核准節點，逐步可查。

評測讓團隊在發布前，用自家資料集測提示、模型或工具的改動，而不是等出事再回推。

原文強調 trace 與評測結果都留在客戶手上——這句話同時是技術承諾，也是採購說帖。

（編輯推論：模型半年換一代，重建的是評測集與 trace 的解讀方式；平台若把這兩件事綁進自家雲，主權就只剩口號。）

兩個自報成效，與一個規模參考

場景原文描述數字與限定語
生產事故調查代理照 runbook 查、敏感動作先要核准、結論貼回 Slack每月省數百小時（Mistral 自報）
產品營運分流模型判斷 bug 或功能需求，規則分派給對的團隊每週約 35 小時（Mistral 自報）
執行環境規模支撐 Mistral Vibe 工作階段的同一套基礎設施每週數百萬次工作階段（原文未給基準日）

兩個成效數字都是自家團隊、自家流程，沒有分母，也沒有第三方驗證。

「每月數百小時」聽起來大，但沒說是幾個人、多少案件分攤出來的。

客戶引述裡反覆出現的理由也不是省時：ABANCA 要留住基礎設施控制權，BNP Paribas 要系統留在自家基礎上。

名單本身也是訊號：銀行、航運、系統整合商同時在生產環境，代表賣的是可交付的專案，不是概念驗證。

開發端的摩擦被壓到一行指令

新的 Mistral MCP server 讓開發者用 Vibe 或慣用的 coding agent 開發、本機測試，再一行指令部署到 Studio。

托管、驗證與執行由平台吃下，團隊只設定代理能碰哪些工具、資料與動作。

原文這次也把 enterprise context 併進 Studio：App 可用搜尋索引取企業文件，並共用同一份脈絡。

（編輯推論：把部署壓成一行，換來的是治理要更前置——權限邊界得在設計時就寫清楚，否則上線後才補會很痛。）

帶走三件事

模型留在可換的那一層。平台與評測才是資產，換代時不重寫。

三種形態別用一種硬幹。簽核點屬工作流，不屬代理。

自報成效先問分母。沒有案件量與人力基準，省時只是形容詞。
