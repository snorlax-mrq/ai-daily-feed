Message threads：省延遲，不省 token

導讀

原文：Anthropic 官方產品說明〈Make long-running agents faster with message threads〉——public beta 上線公告兼機制說明，全文沒有圖表，機制只有一段文字。

claude.com（Anthropic 官方）·2026-11-02 發布·2026-11-03 收錄· 閱讀官方原文

約 35%50 萬至 100 萬 token 請求的 TTFT 中位數降幅，前提是 Claude Code 多數使用者預設開啟（Anthropic 自報）
5 分鐘thread 自最後一次請求起算的存活時間，逾時就得重送全文
1 個參數Messages API 加 thread；首輪送全文，之後只送增量＋上一個回應 ID
0 省token 用量不變：Claude 每輪仍讀完整對話，費率與速率限制照舊

thread 讓 agent 每輪只送新增的訊息與工具結果，換到更短的首字延遲——但 Claude 每輪照樣讀完整段對話，token 一毛沒省。

「請求變小」與「模型讀得變少」是兩件事。thread 縮的是上傳量，不是推論量，所以省下的是等待，不是帳單。

原文的場景很具體：coding agent 一個 session 可能發出數百個請求，每一個都把先前的訊息與工具結果重送一次。

對話長到數十萬 token 後，這段重送就落在模型開口之前，直接計入 TTFT。回合數越多，乘出來越明顯。

官方給的數字是：Claude Code 多數使用者預設開啟後，50 萬至 100 萬 token 的請求，TTFT 中位數下降約 35%。

限定語得跟著數字一起讀：區間是 50 萬至 100 萬 token、指標是 TTFT 中位數，不是 p99，更不是成本。原文未給樣本數，也無第三方驗證。

（編輯觀點：中位數好看，不代表長尾跟著好。長尾往往被工具執行時間吃掉，而工具時間不在 thread 能省的範圍內。）

這個 35% 綁在 Claude Code 的預設值與它的流量上。換成自建 agent、換一種工作負載，就得自己重量一次。

五分鐘 TTL：狀態放記憶體，過期就重來

回合之間，thread 留在平台的記憶體裡，加密、不寫入磁碟。這是原文對存放位置與壽命的全部描述。

（編輯推論：不落盤的狀態撐不過一次服務重啟。原文沒承諾跨重啟恢復，就別把它當持久化的 session 儲存。）

記憶體、加密、不落盤三個詞在講同一件事：這份狀態的壽命以分鐘計，不是以專案計。

過期不是錯誤，是設計。原文要客戶端「重送完整對話、開一條新的」，等於把恢復成本明確外包給 client。

（編輯推論：這是整篇最貴的一條邊界。等人工批准、跑一個長工具、撞上 rate limit 排隊，只要閒置超過 5 分鐘，下一輪就是全量重送。）

（編輯推論：最需要省延遲的慢流程，剛好拿不到這項優惠。）你的 client 得把「thread 已過期」當常態處理，不是當例外。

原文只說過期這件事，沒說平台會不會主動通知。實作上就當它不會：收到錯誤或狀態不符，直接補送全文、開新 thread。

（編輯推論：真正的工程量在 client 端。thread ID 與前一個回應 ID 得跟 session 一起存，串流中斷重試時才判斷得出續用還是重開。）

什麼時候值得開

原文把適用範圍收得很窄：正在活躍、且延遲要緊的 session。它列了三類，共同點是每輪都會自動長出新內容。

場景每輪多送掉什麼開了 thread 之後
長時間跑的 coding agent每一則工具結果、每一次檔案編輯，全部隨回合累加只送增量，重送量不再隨回合數膨脹
Computer use agent每一輪重新上傳的截圖截圖留在 thread 內，請求本身變小
文件與圖片密集流程大量文件與圖片，每輪都隨請求再送一次請求本身變小（原文未說明保留機制）

→ 可橫向滑動

原文補了一句判斷準則：agent 帶的 context 越多，TTFT 能降的空間越大。

（編輯推論：對話只有幾千 token 時，重送的絕對量本來就小。開 thread 換不到多少時間，只換到一層狀態管理與過期處理。）

原文的 35% 只量 50 萬 token 以上的請求；往下的區間沒有數字，只能推論重送佔 TTFT 的比例較低，能省的延遲也有限。

所以這是規模門檻，不是通用開關：對話連續、密集、越長越胖時才值得動。

節奏也綁死：thread 只在同一個活躍 session 內連續跑才有意義；中間一斷，前面累積的狀態就得重新建立。

可用範圍是 public beta：原生 Claude Platform、AWS 上的 Claude Platform、Microsoft Foundry 上的 Claude，以及 Google Cloud 上的 Claude 模型（Anthropic 管理）。

標準 token 費率與既有速率限制照舊。這句話再確認一次定位：你付一樣的錢，買到的只有時間。

帶走三件事

先確認要買什麼。這個功能只賣延遲，帳單完全沒動。

把 5 分鐘寫進錯誤處理。閒置過期＝全量重送，不是異常。

context 越大，省下的越多——但只有時間。小對話開 thread，只多一層狀態。
