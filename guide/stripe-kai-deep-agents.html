Stripe 的答案是分層外包：通用 agent harness 用現成，Stripe 專屬那層自己建——速度與瓶頸都從這裡長出來。

原本各工程團隊在既有的 Ruby、Java 堆疊上自己疊 orchestration 層。接上內部基礎設施不難，難的是做出可靠、可上線的 agent harness。

2024 年底 Claude Code 發布後，全公司都想做 agent，但終端機、資料權限與安全對非工程師是硬門檻。Agent Foundation 團隊反過來問：與其把人推去學開發工具，何不直接給一個常駐、可上線的助理？

這同時是一場語言賭注。Stripe 花十多年在 Ruby、Java 周邊建內部工具、安全層與部署支援；改採 Python-native 堆疊，等於為新語言重建整套服務鷹架，是大投資。

答案就是 Knowledge AI Platform（Kai）：單一 session 介面，接上內部資料倉儲、Slack 與 Google Suite，產出報告、儀表板與文件，隨對話演進。原文的說法是「給非工程師用的 coding agent」。

分界線值得記住：越是通用的能力，越沒有理由自己寫；越貼近公司內規與安全的那一層，才是投資該放的地方。

原文引 AI 平台負責人 Chrissie 的說法：「Kai 完全鞏固了大家相信 Deep Agents 是正確方向。」這句話來自客戶端，但刊登在供應商部落格上，讀者需自行折算。

讓它進到生產環境的三個 middleware

一週做出初版靠的不是省略工程，而是三個 middleware 直接兌現：檔案、沙箱、摘要。

middleware解決什麼原文限定細節
Filesystem讓檔案成為跨回合可讀寫的上下文；Kai 是雲端服務，不是本機執行的程式自建 S3 虛擬檔案系統；每次 sandbox 執行前 sync in、執行後 sync out，整個 session 維持一致的檔案環境
Sandbox跑分析用 Python，也處理 PDF、簡報等多種檔案格式沙箱只暴露為工具，agent 本身跑在外面、呼叫進去，切開 LLM 生成程式的執行邊界
Summarization管理長會話累積的上下文，避免效能退化或撞到模型上限用 deepagents 的 summarization threshold、摘要模型、輸出水準等參數調整；多數使用者間歇使用，避開大 context 的 cache miss 有助控成本

三個 middleware 的共同點是「邊界」：檔案有進有出、agent 在沙箱外而生成的程式碼在沙箱內執行、上下文按門檻壓縮。原文明講，這些若從零自建「要花數個月」才能硬化。

對非工程師使用者，這些機制的體感很單純：上傳簡報、要求分析、拿到圖表，中間不必知道程式在哪裡跑。

（編輯觀點：原文沒給初版程式碼規模與後續維護人月，一週只能讀成「從零到可試用」，不是上線成本。）

skills 一多，選擇本身變成瓶頸

原文對 skill 的定義很具體：可執行的結構化模組，封裝「怎麼做、要載入哪些工具、這類工作怎麼下手」。

維護是聯邦式：各團隊自己擁有 skills。基礎 skills 隨主 agent 出貨，其餘按職能分層載入，銷售營運與財務看到的組合不同。

使用者層另有一層個人 profile，可在職能預設之上再加自己要的 skills。

但 500 多個內部 MCP 工具、1,000 多個 skills 塞不進 context，於是改用 allowedTools 清單做兩段式載入。

原文另有一條硬規則：基礎 skills 會被 pinned，不隨模型卸載而消失，確保 Stripe 的脈絡與政策行為常在。

原文自己承認限制：frontmatter 上限 1,024 字元，而 skills 超過 150 個、再加系統提示時，前沿模型品質已見下滑。團隊仍在找解法。

採用曲線則相反地陡：開放預覽一週就達到季度目標，約四週從 296 人長到逾 5,000 人。

原文說新使用者多是被要求「用 AI」卻一直找不到順手工具的人：業務、財務分析、商業營運。有人形容前一個工具「太難親近，得自己調一堆旋鈕」，Kai 則是「什麼都不用調」。

原文稱現今行銷 95%、GTM 87% 的使用比例高於工程團隊；連工程團隊自己也拿 Kai 查自家系統、跑自己的 traces 找 skill 缺口。

下一個瓶頸是「選擇」本身。原文的規劃是：現在純靠 LLM 選還可行，規模再大就得先由 RAG 或分類器預篩，再由 LLM 拍板。

其餘三件待辦也寫得直白：數千員工規模下的合規護欄、行為層的個人化（有些團隊要 Kai 先計畫再動手，有些只要快問快答），以及目前仍是單人 session 的跨人協作。

帶走三件事

先問哪一層不該自建。通用 harness 已有現成積木，重畫只換到更慢的起步。

一週做出初版不等於規模化。真正的難題在 skill 與工具的選擇。

聯邦式供稿要配治理。100 多個團隊寫 skills，沒有護欄就沒有可預測行為。
