具身代理自進化：不改權重，改 Harness

3 個評測場LIBERO、RoboCasa、RoboTwin，評估時 Harness 程式固定不動

這篇的重點不是更強的機器人模型，而是把 Harness 當成程式碼來演化——動手的是 Meta-agent。

Harness（本文沿用原文用語）指的是包在模型外面的那一層：給模型什麼指令、開放哪些技能、怎麼呼叫工具、怎麼解讀執行回饋。

技能程式、呼叫邏輯與持久記憶，原文都算在「可以開發」的範圍內；模型本身不在其中。

（編輯觀察：這條路線的前提假設是——機器人做不好，常常不是模型不夠聰明，而是外層把它的能力組錯了。）

原文的例子很具體：Meta-agent 能把「定位、學習策略完成的抓取、控制器執行的搬運」串成一個新技能，交給執行 Agent 呼叫。

原文把技能程式、呼叫邏輯與持久記憶都列為「可以開發」的內容，所以改的是程式碼，不是重新訓練。

把「寫」與「評」拆開，是整套方法最關鍵的一刀：自己改的東西不能自己驗收。

Harness 圖保存版本、繼承關係與證據，所以下一輪可以回到較早節點換方向，不必從零重寫。

為什麼不直接調權重？原文的答案是：模型訓練完成後，能力不該就此定型。

（編輯觀點：改進寫成程式，勝負能被外部任務驗證；改進寫成權重，就得靠下一次訓練重來。）

（編輯觀點：凍結權重也讓歸因變乾淨——分數變化只能來自 Harness，不能來自「模型剛好被多訓了一輪」。）

（編輯觀點：長程多階段任務只從 4.7% 走到 13.3%，說明這套方法補的是「流程寫錯」，不是「能力不足」。）

RoboCasa 的 Unseen 欄位最值得看：換到沒見過的場景仍有進展，代表改出來的不是單一場景的特例。

（編輯推論：Unseen 只走到 13.3%，代表外層改得再好，模型看不懂的場景還是看不懂。）

一輪一輪看：奶油乳酪盒上架

第一輪的產物不是分數，而是可繼承的技能：搬運、釋放、有限重試被留下來，後面幾輪再修其中的狀態判斷。

Goal-T 的十個任務裡，有八個在前三輪就出現 16/16；但原文也提醒，不同任務節奏差異大，候選版本表現會波動，要靠評估決定留哪一版。

（編輯推論：這套做法的成本會轉移到「評估場」——任務夠不夠多、夠不夠像真的，決定演化會不會只是背下模擬器。）

原文的下一步寫得很清楚：目前全在仿真裡，團隊希望有一天機器人在真實環境也能自己開發、驗證技能。

那一步的門檻不是演算法，而是評估：真實世界沒有免費的重置鍵，試錯要付物理成本。

帶走三件事

先修外層，再談換模型。Harness 寫錯時，換更強的模型只是更有力地做錯。

自己改的不能自己驗。凍結候選、由外部任務受測，是這套方法的守門條件。

技能要能繼承。沒有 Harness 圖，每輪都是重寫，經驗留不下來。
