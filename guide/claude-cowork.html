30 秒版本

同一份 Claude 在 web、桌面與手機合而為一：對話從 chat 起步，簡單問題照樣快答；當任務需要跑程式碼或處理檔案，Claude 接手到 Anthropic 管理的雲端環境執行 agentic 工作，闔上筆電也繼續跑，完成的文件、分析或簡報回到對話裡。這體驗 9 月先給 Pro/Max，現已 GA 到 Claude Enterprise（採零資料保留、HIPAA-ready 配置或客戶自管加密金鑰的組織維持現有配置）：chats、projects、connectors、skills、plugins 直接沿用；已核准 Claude chat 的組織，SSO 與 Compliance API 照舊；雲端工作階段各自隔離 VM、egress 預設關閉；定價維持用量計價，新增 Efficient mode 等四種用量控制交給 admin。

  • 使用者不必再選工具：chat 與 agentic 工作在同一條對話軸上切換，跨 web／桌面／手機接手。
  • 企業買單的是可控性：角色存取、SSO、Compliance API、隔離 VM、egress 預設關、憑證在沙盒外、預設不訓練。
  • Agentic 工作比聊天吃 token，官方以「更便宜的模型＋四種 admin 開關」回應成本治理。

從「該用哪個 Claude」到開口就好：統一體驗怎麼運作

這個問題原本是真的存在：Quantium 說，客戶不斷問他們 「which Claude should I use」、「which one does what」。統一之後，團隊成員開工前不再先做選擇題：對話以 chat 開始，簡單問題照樣快答；需要跑程式碼或處理檔案時，Claude 在同一條對話裡轉入雲端，完成後把文件、分析或簡報交回。因為工作跑在雲端，闔上筆電也不中斷，可以在 web、桌面或手機接手——Carvana 的用法正是如此：桌機起頭、手機接續，Claude 有結果或需要輸入時推播通知。

遷移成本被刻意壓低：chats、projects、connectors、skills、plugins 全部沿用；有客戶引述整個過程 seamless，connectors、skills、MCP 沒有壞任何東西。成效引述裡最具體的一則：有組織用不到十分鐘的提示，讓 Claude 讀完整疊郡、州與聯邦預算及公開會議文件、畫出資金流之間的連接，產出一份原本要花團隊數週的綜合報告——整趟過程使用者不必決定哪一步該用哪個工具，報告將影響其策略規劃與預算流程。

企業級安全：隔離 VM、egress 預設關、憑證在沙盒外

對已核准 Claude chat 的組織，這次合一建立在既有企業控制上：SSO 與 Compliance API 照用；Anthropic 持續在傳輸與靜態時加密資料，且預設不用於模型訓練。

Agentic 工作跑在雲端工作階段（cloud sessions），每個階段一台隔離 VM，網路 egress 對 Claude Enterprise 預設關閉，連接器憑證留在沙盒之外。因為工作集中在 Anthropic 管理的同一環境，安全團隊能取得中央可視性與控制；完整架構見 Anthropic Trust Center 的安全最佳實務指南。

為什麼「集中在一家管理的環境」反而是賣點。原文的邏輯：正因為 agentic 工作全部發生在同一個由 Anthropic 管理的環境裡，企業安全團隊才有一個單點可以建立可視性與控制——散落在各端點裡跑的 agent，治理成本反而更高（編輯推論）。

用量與成本：Efficient mode 與四種管理控制

定價維持用量計價。官方同時給了降本數字：以用量計費，Claude Opus 5.5 在典型工作負載下比 Opus 5 便宜 40%；Claude Sonnet 5.5 對多數工作最多便宜 30%。但硬幣的另一面也被直白說出：依任務不同，agentic 工作的 token 消耗可能高於一次快問快答——所以官方給 admins 四種控制來管理這類用量。

原文列出四種：Efficient mode（新設定，讓統一體驗維持在 Sonnet 與 Haiku 模型上）、model entitlements（按角色設定各角色可用哪些模型）、spend limits（套用在組織、群組與成員三個層級的花費上限）、pooled group budgets（群組共用一筆每月額度）。

帶走三件事

介面的終點是取消選擇題。統一把「何時用 chat、何時用 agent」的判斷從使用者手上拿走——你描述意圖，切換工具變成模型與平台的事；Quantium 聽膩的那兩個問題，正是這類產品要消滅的摩擦。

企業採用的門票是治理面。公告用同等篇幅講功能與控制：角色存取、SSO、Compliance API、隔離 VM、egress 預設關閉——雲端 agent 得先「可管」，才敢「可用」。

成本已是 agent 產品的一級問題。Agentic 工作天然比聊天吃 token；官方的回應是兩端同時做：模型更便宜（-40%／-30%）＋admin 端四種開關——用量治理是內建功能，不是事後補丁。
