真正的新東西：把 agentic 的帳單關起來

同一段原文承認：agentic 工作比快問快答吃更多 token，所以成本治理才是這次的實質改動。

1Efficient mode新設定：把統一體驗鎖在 Sonnet 與 Haiku
2Model entitlements逐角色指定能用哪些模型
3Spend limits組織／群組／成員三層皆可設上限
4Pooled group budgets群組共用一筆月額度

四項並列、無先後，原文同段連續列出（本站整理）。另有一項與用量分開敘述的「依角色控制雲端工作階段存取」，屬存取控制而非用量控制。

定價維持用量計價。模型本身也更便宜：Opus 5.5 在典型工作負載下比 Opus 5 省 40%，Sonnet 5.5 對多數工作最多省 30%（皆為 Anthropic 自述）。

隔離怎麼做

  • 每個雲端工作階段跑在自己的隔離 VM，不是共用環境。
  • Enterprise 的網路 egress 預設關閉。
  • 連接器憑證留在沙盒之外，不隨工作階段進去。

因為環境只有一個、由 Anthropic 管理，安全團隊拿到的是集中可視性與控制——原文指向 Trust Center 的 security best practices 指南說明完整架構。

客戶引述最值得看的一則是規模：某組織用不到十分鐘的提示，讓 Claude 讀完郡、州、聯邦預算與公開會議文件，畫出資金流的連接，產出一份原本要數週的報告（單一客戶自述）。

帶走三件事

選工具的問題消失了，選模型與預算的問題出現。產品收斂，治理反而更細。

「闔上筆電也繼續跑」是這次最實在的差異。它把 agent 從桌面程式變成佇列服務。

−40%／−30% 是執行成本、不是售價。用量計價下，省下的取決於你的工作型態。
