iFood 代理規模化：缺的是執行層，不是模型

導讀

原文：OpenAI 客戶案例〈How iFood scales coding agents across 15,000 repositories〉——案例訪談兼架構說明（受訪者 Victor Coelho，iFood 資深軟體工程師）

OpenAI·2026-11-24 發布·2026-11-25 收錄· 閱讀官方原文

逾 15,000 個 repoiFood 維護的程式碼儲存庫，每個都要週期性驗證、修依賴、跑分析
逾 25,000 次任務平台累計完成數，覆蓋全部 15,000 個 repo
逾 270 億 token同期累計消耗；全部執行都用 GPT-5.6 Luna
平均 US$0.04／次每次執行成本，原文稱規模化後成為架構決策

iFood 把 repo 維護變成一通 REST 呼叫：交出 prompt 與環境需求，回來一份 merge request，判斷留給沙箱裡的 agent。

原文稱這是一個三步的 cycle，對外敘述更直白：工程任務變成 API 呼叫，交辦後成果以 merge request 回來。

平台自己管生命週期，沙箱只是執行單位；使用者只需要 prompt 與環境需求兩樣輸入。

問題不在任務本身。驗證程式碼符合內部標準、修脆弱依賴、跑一份分析，單看都不難。

難的是同樣的事乘以一萬五千次，還要週期性重來，每次都得有人記得去做。

原文引 Coelho 的話：「解決一個 repo 很容易，挑戰在於規模化。」

平台之前，各團隊各寫一套解法，最後都撞上同一道牆。

原文的診斷很明確：缺的不是智慧、也不是場景，而是執行基礎設施——一個專用 runtime。

（編輯觀點：這一步把「跑 agent」從開發者本機的臨時動作，變成可排隊、可計價的服務呼叫。）

兩段固定手續，夾住中間的判斷

runner 內部交錯兩種步驟：deterministic 與 agentic。這個組合讓整體流程可預測。

階段執行者做什麼
開頭・deterministic 平台固定步驟 clone repo、匯入 agent 可用的 skills、建立工作分支
中間・agentic 沙箱內的 GPT-5.6 Luna 自行判斷與修改；Ubuntu 預裝 8 種語言工具鏈，沙箱外可連 Nexus、GitLab、Docker、Snyk、Kubernetes、AWS
結尾・deterministic 平台固定步驟 發 merge request、釋出產出的 artifacts

原文只用一句話交代這個設計：「就是這兩件事的組合。」

agent 的判斷因此被框在一個區間裡：前面有人幫它 clone 與開分支，後面有人收尾。

固定步驟管可預測的部分，agent 只管中間需要判斷的部分——界線畫在工具鏈，不在 prompt。

沙箱預裝 Python、Java、Kotlin、C#、TypeScript、Rust、JavaScript、Go，另加通用工具。

這是把「跑得起來的環境」變成平台責任，而不是每個任務各自準備一次。

（編輯推論：八種語言加六個外部系統，等於把「環境」也標準化；這才是各團隊碎片化解法收不回來的那一層。）

選型看三件事，驗收看一份契約

選 GPT-5.6 Luna 是三個因素一起看，不是單項取勝。

原文的說法：同級 checkpoint 中，它在智慧、效率、執行速度（多快做完任務）三者平衡最好。

一次性用途看不出這個平衡值多少；平台看得出。

數萬 token 的量級下，平均每次 0.04 美元不再是細節，而是架構決策。

要注意原文只給累計值與平均成本，沒有中位數，也沒有單次任務的成本區間。

驗收也自動化：執行完成後，用 OpenAI 的 Structured Outputs 要求輸出符合預先定義的契約。

契約一致，成功與失敗都能從回應結構辨識，不必逐筆打開來看。

驗收發生在 session 之後的那一步，與執行本身分開——這是規模化的關鍵設計。

第一個主要用戶是內部安全平台：掃 15,000 個 repo 的脆弱依賴，並嘗試修補。

原文的副標就是成效：透過安全平台修補的漏洞數。

改用平台後，修補準確率與已解決漏洞數都超過原本兩倍（iFood／OpenAI 自報，無第三方驗證）。

安全團隊沒有自建 agentic runtime，也沒有變成 orchestration 專家，只是呼叫一支 API。

非同步的價值寫得很克制：開發者開會時丟一個修補、一份效能分析進去，不必守著。

用詞值得注意：原文強調的是「釋放」開發者的時間，不是「取代」開發者。

例行工作不再搶注意力；增益來自不必監看，而不是任務變快。

靈感來自 OpenAI 的 Batch API 與 Agents API，連介面設計、資源組織都一併參考。

下一步是擴到更多情境；能不能規模化，取決於每次任務的成本。

（編輯推論：新增情境的邊際成本，會決定這個平台是留在安全掃描，還是變成公司的通用執行層。）

帶走三件事

門檻在執行層。模型誰都買得到，sandbox 與 runner 才是差異。

成本是架構約束。每次 0.04 美元，15,000 個 repo 才進得了預算。
