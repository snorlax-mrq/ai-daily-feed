Cogent 賣的不是掃得更快，而是把「修」拆成可授權的動作：先有企業脈絡與權限邊界，才輪到 agent 自己動手。

Cogent Security 為企業建「網路防禦工廠」，讓 AI agent 自主找出並消除風險，設計目標是讓防禦方以機器速度移動。

原文的因果很直接：漏洞被發現與被利用都在加速，防禦若還靠人排隊處理，修補永遠追不上。

找到漏洞不難，難的是修。修補跨多個團隊，還得判斷攻擊者怎麼利用、哪些業務系統受影響、什麼改動才安全。

三層各有職責：圖譜給共通知識，模型層分工推理，政策層決定「能不能動手」。

脈絡層的細節值得記：背景 agent 持續在不同資安工具之間對帳，調查與修補 agent 才拿到同一份環境理解。

agent 的三個動作也都落在同一個許可框架內：評估曝險、執行被允許的變更、確認風險已消除。

Sng 把脈絡重用說成「企業的記憶 harness」：不必每接一個新任務就重新認識世界。

原文給的好處是延遲、推理成本與結果不一致都下降，但未給任何幅度。

取捨寫得很明：複雜調查買推理品質，例行工作買成本。這是能跑大量 agent 的前提。

Sng 的說法是 OpenAI 模型「相對其他供應商更省成本」，對跑大型 agent swarm 是一大加分。

自建的量也少了：harness 層的工作「很多已不再需要」，API 另簡化了請求路由與 agent 調度。

原文只說內部工程負擔顯著降低、複雜安全工作流程更快上市，未給數字。

選型理由有一段是比較級：Cogent 稱自己持續評估閉源與開源替代方案，結論是 OpenAI 模型在長跑型安全工作上推理較強、技術程式碼的幻覺較少（Cogent 自報，原文未給評測方法）。

權限：把「可以改什麼」寫成政策

三種並列選項，客戶按風險自行選擇（原文未給排序或對照）

A只委派調查找系統、評估曝險，變更仍由人決定
B變更要核准政策定義哪些改動、誰來核准
C有界自主修復只在政策允許的範圍內自動執行

政策的內容由每家企業自己定義：允許哪些變更、哪些必須先核准。

動手前有兩道關卡：TRACE 把工具呼叫逐項比對政策，Agent Gateway 獨立查授權。

原文把這個選擇權留給客戶，沒有預設全自主——三種選項對應的是不同的風險胃納。

高風險工作可進獨立沙箱執行；原文未給隔離規格，也未給政策的誤擋率。
