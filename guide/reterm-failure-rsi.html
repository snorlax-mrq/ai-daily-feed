Code Agent 的失敗很少是「答錯一題」，而是把環境弄壞之後還沿著錯假設往前走。

終端任務的糾錯比改一題答案難：錯誤動作已經改過檔案、裝過依賴、起過行程。

Agent 要繼續，得先搞清楚「剛剛到底發生了什麼」，才能判斷問題在哪一層。

原文的 PyStan 案例最能說明差距：套件明明裝好了，import pystan 卻一直報錯。

標準 GRPO 訓練的模型反覆匯入、解除安裝、重裝，始終沒跳出錯誤方向；ReTerm 版則去看安裝路徑，發現模組落在 stan 目錄，改用 import stan 就通了。

關鍵設計是「起點」的選擇：不從乾淨環境學成功軌跡，也不人工注入錯誤。

理由是這兩種做法都不像模型真正會犯的錯——前者覆蓋不到爛掉的狀態，後者錯得不像它。

原文把這稱為自身的「失敗現場」：環境已被前一步改動，後續動作面對的是一個被改過的世界。

（編輯觀點：這也是為什麼「重跑一次」沒有用——重跑換掉的是環境，不是策略。）

冷啟動的 ReTerm-10K 則補上示範：由更強教師模型接手失敗任務，示範如何檢查、修復、完成，再篩掉品質不夠的軌跡。

先學會「接手爛攤子」，再進到線上 RL 去解決自己新產生的問題，這是原文安排的順序。

消融把功勞分得比較清楚：恢復示範 SFT 讓 20.2% 到 25.8%，標準 GRPO 到 28.0%，ReTerm-GRPO 才到 34.8%。

也就是說，在「已經用 RL 練過」之上，專門練恢復行為還多賺 6.8 個百分點。

原文另註明：ReTerm 與 Qwen3.5-9B 用同一套執行框架與評測配置，其他模型的數字取自各自論文或官方發布，配置未必相同。

換句話說，原文只點名 ReTerm 與 Qwen3.5-9B 共用框架與配置，其餘跨模型比較要打折看。

同一批實驗也顯示，9B 這種規模在部分評測上贏過參數更大的模型，但仍要放回上面那句配置差異一起讀。

換框架、換任務，增益還在不在？

跨到數學推理與表格操作也有提升（AIME 2024、Aider Polyglot 同樣上升），原文的說法是展現跨任務領域的泛化潛力。

（編輯觀點：真正稀缺的不是「會重試」，而是「知道該去哪裡找證據」——PyStan 那一手看的是安裝路徑，不是再試一次。）

（編輯推論：若四類錯誤的恢復率卡在三成以下，下一步的瓶頸可能在驗證器：有些失敗無法用最終答案判定對錯。）

原文的收尾把定位講明白了：失敗從一次執行的終點，變成後續學習的材料。

它給的是可實驗、可分析的切入點，而不是宣稱 Agent 已經能自我進化。

（編輯觀點：這條路吃得下多少任務，取決於「做完了沒」能不能被自動判定；開放式任務往往沒有這種驗證器。）

帶走三件事

失敗要留現場。沒有環境與操作紀錄，就只剩下「重跑一次」。

只練恢復才划算。同樣用 RL，專練恢復比一般訓練多 6.8 點。

驗證器決定上限。判不出對錯的失敗，進不了這個閉環。
