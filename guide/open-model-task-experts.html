Shopify 的 AI 購物助理 Sidekick 由前沿模型負責對話與規劃，token 重的專門工作交給「任務專家」——針對單一任務後訓練的開源模型。GraphQL 子代理換上後訓的 Nemotron 3.5 Lightning 之後：品質分 74.5 微超前沿模型的 73、回應快 7 倍、服務成本低約 90%，秘訣是一條每晚自我修復、持續轉動的學習飛輪。

  • 子代理的工作極度「讀多寫少」：GraphQL 子代理每寫 1 個 token 要讀約 40 個，而前沿模型 API 逐 token 計費——換算下來，成本主要壓在 context 上。
  • 飛輪六步：定義品質（rubric → LLM 評審）→ 先榨乾前沿代理 → 實測選開源模型 → 推論優化 → 失敗對話自動變訓練料 → Blackwell 上後訓練；評審重新打分後再轉下一圈。
  • 自我修復機制在 86 個夜間批次修好 59,535 則失敗對話（成功率 69%）；修不好的由人類修正，修正結果回頭校準評審。

問題：子代理是「token 大胃王」

Sidekick 的分工是典型的主從架構：前沿模型負責跟商家對話、規劃工作、決定呼叫哪些工具；聚焦的子任務則交給子代理。以 GraphQL 子代理為例——商家問「哪些商品快缺貨了」，它要讀 Shopify 的 API schema、查文件、寫出查詢、跑出結果再回報。這種工作有個成本結構上的致命傷：每寫 1 個 token，就要讀約 40 個 token，而前沿模型 API 是逐 token 計費的——40:1 的讀寫比加上計費方式，成本主要壓在 context 上（由讀寫比推算）。

Shopify 的解法不是換更便宜的前沿模型，而是為這個任務專門後訓練一個開源模型：GraphQL 子代理換上後訓的 Nemotron 3.5 Lightning，品質略高於前沿模型、回應快 7 倍、服務成本低約 90%。更關鍵的是主權——後訓練的權重歸 Shopify 所有，跑在自己的 GPU 上，何時更新自己決定。這些「任務專家」的生產線，是一條帶硬體加成的持續學習飛輪。

讀寫比約 40:1逐 token 計費context 多是 schema 與文件專門任務用不到通用智能權重在別人手上

飛輪總覽：三步設定定目標，迴圈帶著新資料反覆轉

六步逐一拆解

01定錨

定義品質：先造尺，再做事

產品專家把需求寫成評分 rubric（GraphQL 覆蓋完整性、執行、回應品質三個構面）；兩位專家對同一批對話的評分一致程度，設為評審必須達到的門檻。接著用 GEPA 與 ACE 優化器調校 LLM 評審，直到它與留出的人類標籤一樣準。此後，所有 agent 變更、候選模型、訓練 run 都由這把尺打分。

02墊高

先榨乾前沿代理，再談換模型

開源模型進場之前，先用 autoresearch 迴圈把前沿模型版本推到極限：一次只提一個小改動（prompt、工具描述或控制流），評審分數提高才保留。改良後的前沿代理，就是開源模型必須打敗的基準線。

03實測

選模：放進真實子代理裡比，不是看榜單

Shopify 不做預訓練。候選開源模型放進真實子代理，用同樣的工具與評審實測，權衡三件事：起始品質、服務速度、以及 NVIDIA Megatron Bridge 的支援度（他們用它訓練）。GraphQL 選了 Nemotron 3.5 Lightning——混合專家（MoE）架構，300 億參數中每個 token 只活化 30 億。

04測速

推論優化：太慢的模型不值得訓練

從第一天就測服務效能：用 NVIDIA Dynamo 裡的開源負載測試器 AIPerf，以合成文字重播生產軌跡（不碰客戶資料）；Shopify 貢獻的 live-response replay 讓多輪測試能像生產環境一樣命中伺服器的 prefix cache。選堆疊也靠數據：Buyer Profile 批次工作負載比較 vLLM、SGLang、TensorRT-LLM，結果 TensorRT-LLM 每 GPU 產出最高。

05修復

失敗變訓練料：每晚的自我修復迴圈

每晚評審抽測一批生產 GraphQL 對話，未達滿分就進自我修復（見下圖）。近期 86 個夜間批次修復了 59,535 則對話——占嘗試修復件數的 69%；修不好的由人類標註員修正，這些修正同時成為校準評審的 ground truth。

06練兵

Blackwell 上後訓練：硬體讓每圈更便宜

後訓練用 NVIDIA Megatron Bridge：把標準 Hugging Face checkpoint 接上 Megatron Core 訓練庫，不必重寫模型；跨節點擴展在 Nebius 上只需改設定、不必改程式。同樣的 FP8 後訓練（Analytics 模型）：8 張 B300 比 8 張 H200 快 1.86 倍、GPU 時數省 46%。新 checkpoint 由評審打分，飛輪再轉。

五個關鍵詞

任務專家 Task Expert為單一任務後訓練的開源模型，在真實子代理裡上陣。「專」讓小模型也能打贏通用大模型。
LLM 評審 Judge用 rubric 校準到與人類標註一致的自動評分器。沒有可信的尺，就沒有可信的迭代。
自我修復 Self-healing失敗對話 → 提示重跑 → 評審把關 → 訓練範例。生產環境的失敗，從負債變成資產。
Autoresearch一次一小改動、評審通過才保留的自動迭代迴圈。把「調 prompt」從玄學變實驗。
Megatron Bridge把 Hugging Face checkpoint 接上 Megatron Core 的橋。換模型＝改設定，不是重寫訓練管線。

帶走三件事

先讓「好」可測量。Shopify 投入最多心力的不是訓練腳本，而是 rubric 與評審校準——評審一致度追平人類之後，每個變更、模型、訓練 run 才有同一把尺。

換模型是最後一步。先用 autoresearch 榨乾前沿代理，墊高基準線之後，開源模型的目標是打贏它；跳過這步直接換模型，只會得到「堪用」。

失敗是資產，權重是主權。每晚自我修復把生產失敗轉成訓練料；自持權重＋自有 GPU，讓服務成本省約 90%（各後訓模型自託管全線 90–98%），也拿回「何時更新模型」的決定權。
