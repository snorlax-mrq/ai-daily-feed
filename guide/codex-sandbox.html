代理沙箱：預設保守，邊界交給作業系統

Codex 沙箱不是 VM，也不是容器：它用各平台原生的沙箱機制，把代理在你電腦上執行的指令，關進你指定的檔案與網路邊界。

原文把它歸在 defense in depth：訓練與對齊、harness、作業系統三層各管一段，沙箱只負責「指令執行時碰得到什麼」。

定義很樸素：限制程式執行時能存取的東西。照片整理只開 ~/Pictures 並斷網，避免檔案被上傳。

程式碼審查反過來：線上文件可查、原始碼唯讀。邊界是按任務配的，不是一套打天下。

不搬進容器的理由寫得很具體：筆電是客製環境，Docker 裡跑不了 iOS 的原生建置鏈，也開不了模擬器。

若把建置與模擬器丟回主機執行，那些動作又跑到沙箱外，得另外再圍一次。

（編輯觀點：這是拿隔離完整度換工具鏈可用，界線得靠 profile 一條條補，而不是靠一層牆。）

:workspace 的三條預設，與各自的代價

permission profile 就是一個 session 的檔案與網路界線；內建的 :workspace 以 Git repo 當工作區根。

邊界可寫唯讀可讀網路
:workspace（內建）工作區內，.git 與 .codex 除外.git（含 hooks）、.codex/config.toml全機，但受使用者原有的 OS 權限限制全關（預設）
dev（延伸 :workspace）多一個 ~/build-cache.vscode（在每個 workspace root）繼承 :workspace 的廣泛讀取走代理，只放行 *.openai.com，evil.example 明示拒絕
stdio MCP（未包沙箱）全機，與執行 Codex 的使用者同權限無，不套用任何 profile全機無限制

→ 可橫向滑動

工作區可寫，換來代理改檔案不必每次問人；.git/hooks 與 .codex/config.toml 唯讀，是為了不讓它改到自己或改到掛鉤。

讀取放寬到整台機器，因為編譯器、runtime、建置工具都要讀 workspace 以外的程式庫與設定；代價是含 API key 的設定檔也讀得到。

網路預設全關：擋掉上傳與外洩，也擋掉下載依賴，要開得另外授權。

profile 的檔案規則只有三態：read 唯讀、write 可讀寫、deny 直接封鎖。

:workspace_roots 讓同一條規則套到每個 root；CLI 以工作目錄當唯一 root，ChatGPT 桌面版用專案的來源資料夾。

沙箱擋不住的部分，原文直接示範：模型可把惡意程式碼寫進被 Git 忽略的 node_modules，git status 看不到。

之後你按存檔，編輯器跑起那個套件，程式就在沙箱外執行了。這是原文主張分層、而非單靠沙箱的理由。

（編輯觀點：這裡防的是「你沒同意的動作」，不是「所有壞事」；誤讀成後者最容易鬆懈。）

企業那層另備 requirements.toml，例如用 allowed_permission_profiles 把 :danger-full-access 鎖掉。

分層靠合併：多份 config.toml 疊起來，表遞迴合併、陣列整段取代。權限用表存路徑與網域，團隊才只覆寫一條。

一組 API，三種作業系統的執法方式

harness 用同一個 API 啟動指令：指令加 profile，需要限流量時再附一個網路代理，回傳 Child 讓它等結束。

沙箱不只給 shell 工具：讀寫本機檔案也走同一套，codex sandbox 則把它從 session 裡拆出來給你的工具。

平台原生機制檔案規則怎麼下網路怎麼斷
macOSSeatbelt，走 /usr/bin/sandbox-exec，政策寫在 SBPL從 base policy 疊出 profile，起點是 (deny default)只放行代理所在的本機埠
Linuxbubblewrap 加 seccomp-bpf，由 codex-linux-sandbox 統籌--bind 可寫、--ro-bind 唯讀、--perms 000 --tmpfs 拒絕--unshare-net；seccomp 封 connect(2)、bind(2)
WindowsMXC（Microsoft eXecution Container）；原文限定：在相容的 Windows 裝置上正替換舊沙箱預設拒絕，再給磁碟根唯讀；deny glob 先展開成實際路徑共用代理，只准連主機 loopback

→ 可橫向滑動

限制沿 process tree 繼承，連活過原程序的後代也在界內；管的是整棵樹，不是那一行指令。

代理只放行 profile 允許的網域；未知網域會暫停請求，交給你或 auto-review 裁決。

判斷順序也有講究：先決定放行才解析 DNS，因為光是查詢就會洩漏網域。

代理預設同時開 HTTP 與 SOCKS5，用 *_PROXY 環境變數注入；但並非每個程式都吃這套，直連仍由平台層擋。

Apple 已在 man page 把 sandbox-exec 標成 deprecated，但 Chrome 等仍在用；原文說在「可預見的未來」仍會沿用。

Linux 那層另設 no_new_privs，避免子程序靠 setuid 提權；bwrap 自帶副本，使用者沒安裝也能跑。

Windows 換掉舊沙箱的理由很務實：舊版要管理員權限、ACL 檢查慢、還會在主機留下使用者與防火牆規則。

MXC 的檔案政策預設拒絕；可寫的磁碟根授權不遞迴，要把根目錄既有子目錄展開，同一路徑取最嚴規則。

模型可以對單一指令要求更大權限，但裁決權在 harness：use_default、with_additional_permissions、require_escalated 三種，可能問你，也可能轉 auto-review。

codex sandbox 也常用來驗證 profile：把 .vscode 改成存檔即跑惡意 formatter，dev profile 會因該目錄唯讀而失敗。

自己要用，codex sandbox --permission-profile X <cmd> 能把同樣限制套到別的程式；stdio MCP server 預設不被包進沙箱，值得自己補一圈。

MCP 的補法是先把套件灌進 npm 快取，再用 npx --offline 在斷網 profile 下啟動。

帶走三件事

預設保守是設計，不是保守心態。先畫小邊界，再逐項放行。

斷網同時擋外傳與依賴下載。要開就指明網域，別整片打開。

沙箱管可及範圍，管不到用途。存檔觸發的惡意碼得靠對齊與人。
