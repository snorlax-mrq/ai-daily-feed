代理沙箱選型：把致命三合一收窄到可管

導讀

原文：LangChain 部落格〈How to Choose the Right Sandbox for Your Agent〉——選型指南，先講風險模型，再列五項規格與兩種接入模式

LangChain·2026-10-01 發布·2026-11-19 收錄· 閱讀官方原文

3 個條件致命三合一：私密資料、不可信內容、對外通訊同時成立，一次注入就可能外洩
OWASP LLM01原文引此風險條目：目前沒有萬無一失的方法阻止 prompt injection
microVM隔離層級：沙箱跑自己的核心，不必為每個沙箱開一台完整 VM
2 種接入agent 住沙箱內，或把沙箱當工具呼叫；後者代價是每次執行跨網路

沙箱不是防火牆，而是你借給代理的一台可丟棄電腦：它不消除三合一，只把三邊收窄到你管得動的大小。

原文對沙箱的定義很樸素：代理能在裡面執行程式、安裝套件、處理檔案，碰不到你的主機與其他基礎設施。

原文開場就講明：讓代理寫並執行程式，是它能創造價值的主要方式之一，風險也正好集中在那裡。

Simon Willison 是 Django 的共同作者，也是「prompt injection」一詞的提出者；三合一就是上面那三格。

重點在那個「同時」：單獨一項都是正常功能，三項湊在一起才變成外洩通道。

原文說得很直接：目前沒有萬無一失的方法阻止注入，不可信內容進到 context 的路徑又很多。

既然擋不住，策略就從「不讓它被騙」換成「被騙了也拿不走東西」。

提供工具通常同時給了私密資料與連外能力；模型越能吃 context、第三方擴充越多，注入入口就越多（編輯推論）。

Meta 把三合一延伸成「Agents Rule of Two」：三項同時成立的 session，不該讓代理全自主。

原文轉述 Meta 的建議是加上人工核准，或另一種可靠的驗證方式。

電子郵件助理是最好的例子：讀陌生來信、開私人信箱、又能寄信，三項一次到位。

原文的結論很克制：沙箱不會消除三合一的任何一角，只把存取與出口收到團隊能掌握的程度。

（編輯觀點：沙箱管的是「碰得到什麼」，不是「會不會被騙」。注入照樣成功，只是拿不到東西。）

四個維度，加一個隔離層級

原文列五項規格：隔離檔案系統、限制網路、資源上限、可控重用、核心層隔離。

維度原文要求可用性代價（本站推論）
隔離檔案系統只放代理做事需要的資料，其餘封鎖，才好稽核工具鏈、套件快取、設定檔要另外準備或掛載
限制網路由你指定可連的對外端點，洩漏也只能送去你信的地方新依賴與新 API 要先進白名單，否則任務直接失敗
資源上限限 compute、記憶體與執行時長，被攻破也不能吃垮系統長任務會被砍，得拆段或調高上限
可控重用重用能延續狀態，但要不要承擔此風險，原文交回使用者自己決定每次開新的最安全也最慢；重用換速度也換風險
核心層隔離沙箱跑自己的核心（microVM），擋住靠核心漏洞提權每沙箱一個核心，啟動與記憶體成本高於共用核心的容器

→ 可橫向滑動

第五項不是勾選項，而是前四項能否生效的前提：容器共用主機核心，核心一破，隔離就等於沒有。

原文點名 Kubernetes Agent Sandbox 這類方案：只有叢集真的做了容器間核心隔離才安全，而多數叢集沒有。

原文還提醒：市面上有自稱沙箱、卻沒內建這些控制的產品，挑之前要逐項驗。

microVM 的價值在這裡——拿到獨立核心，卻不必付整台 VM 的啟動成本。

資源上限不只是防浪費，也讓一次失控的迴圈在燒完預算前停下來。

四道控制都會吃掉可用性；原文要的是收窄到「團隊管得動」，不是全鎖。

重用與否被原文寫成明確的風險決定題：它把判斷交回你手上，不給預設答案。

（編輯推論：白名單與重用這兩項最痛，它們直接決定代理能不能自己跑完長任務。）

決策其實只剩兩個問題：代理要不要讀私密資料、要不要連外。

兩者都要，就不是再加一道牆能解決的事，得在流程裡插人。

代理住進沙箱，還是把沙箱當工具

接入方式有兩種，原文引 LangChain 執行長 Harrison Chase 的區分。

工具模式多出來的那一段網路，換到的是代理邏輯與執行環境解耦。

代價寫得也直白：每次執行呼叫都跨網路，延遲換彈性。

原文說 Deep Agents 兩種都支援，沒有替你選；判準是代理多久改一次（編輯推論）。

（編輯推論：金鑰不進沙箱比延遲更該優先考慮——金鑰在裡面，一次注入就等於交出鑰匙。）

原文後段介紹自家 LangSmith Sandboxes：每個沙箱一個專屬 microVM、授權代理在流量離開沙箱後才注入憑證。

這兩點正好對上前面幾項要求；其餘成效原文未給數字（編輯觀點：末段屬產品介紹，選型仍應逐項核規格）。

帶走三件事

先確認三合一是否成立。成立就別讓它全自主，插人工核准。

容器不等於沙箱。共用核心的隔離，核心一破就全破。

白名單與重用是取捨核心。收窄到管得動，不是收到不能用。
